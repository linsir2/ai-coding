# 10 · 我们的思考与回答编排（代码级）

> 主题：用户输入之后，我们的编排层如何编排模型的"思考"与"回答"。
> 姊妹篇：`08`（dsh）、`09`（opencode）为并行 agent 产出；本文件为逐行自核。
> 一句话结论：**"薄静态提示 + 厚动态干预 + 单向下行的推理管线"**——知识密度全在 tail 与门，静态认知提示只有一句话。

---

## 1. 推理管线：捕获 → 展示 → 落库 → 回喂（四态）

| 态 | 实现 | 证据 |
|---|---|---|
| 捕获 | `reasoning_content`/`reasoning` 流式增量归一 join 进 `StepResult.reasoning` | `ai/openai_engine.py:382,415-424,451` |
| 展示 | `AssistantMessage(text, tool_calls, reasoning)` 事件 → bridge 映射成 wire `{text, reasoning}` → 前端 `reasoning` part（"Thought" 行，ctrl+t 切换显示） | `core/agent_loop.py:1379-1381`；`server/bridge.py:102-106`；`frontend/src/state/session.ts:23,324-338` |
| 落库 | 成功步经 `assistant_message(step)` 把 reasoning 存进 `ChatMessage.reasoning`（非空才写）；**thinking-only 步刻意不落**（无 text/tool_calls 的 assistant 会被 provider 拒绝，落库会毒化后续回合） | `domain/message.py`；`agent_loop.py:1393-1401`（M7 注释） |
| 回喂 | **不回喂**：engine 序列化不含 reasoning（全仓请求路径无 reasoning 读取；DeepSeek 官方语义也要求不回传，且保护前缀缓存字节稳定） | 请求路径 grep 无命中；`message.py` 前缀缓存纪律注释 |

对照（详见 11）：dsh=存+带 signature 回喂（不可用降级）；opencode=存+同 provider 原样重放（跨 provider 降级为 text）。**三家三态，我们是唯一"完全不喂"**。

## 2. 思考失败的防线（三家独有的我们这一层）

- **`ThinkingOnlyStepError`**：只思考没回答 → 有界一次重试，注入"你刚才只输出了思考内容，没有给出最终答案。请直接给出最终答案。"；`finish_reason == "length"` 排除（长度截断重试只会重现）；`session.thinking_retries` 进程内计数保一次。 | `agent_loop.py:619-650`
- **`EmptyStepError`**：无 text/tools/reasoning 三无步 → 失败回合（响亮的域错误，不是 IPC 兜底）。 | `agent_loop.py:1385-1386`
- 对照：dsh **没有** thinking-only 处理（正常 stop 收尾；唯一防线是 0-block 的 `EMPTY_RESPONSE` 重试）；opencode 只思考算 outputStarted → 要么续写要么直接当回答。

## 3. 塑形思考的提示词：静态薄，动态厚

- **静态（system）**：`BASE_INSTRUCTIONS` 只有一句（"You are an AI coding assistant…"）+ 项目指令 + plan-mode 段 + skills 目录。**没有工具使用方法论 section**。 | `ai/prompt.py:14-52`
- **动态（每迭代 tail，声明序，不进 history）**：memory → mcp_catalog → task → recommended_skills → referenced_files → error_recovery → anchor → hook → digest → budget。 | `core/request_assembly.py:259-272`
- 对照（真缺口）：dsh 每个工具自注册 section（bash 查 exit code、read 不用 cat、编辑前先读、jobs 不轮询…）；opencode `system.txt` 15 行 + 按工具集注入指引（shell/write/edit）。**"怎么思考"的第一层（方法论）我们近乎为零。**

## 4. 回合内认知干预：我们的最厚层（也全是提示词补丁）

- **门与 nudge**（持久化的 synthetic user 消息）：`[task-gate]` 未完成项（≤2）、`[strategy-gate]` 连续失败（≤1，"先读错误、换手段、切小目标"原文）、`[fatigue-gate]` Paris 疲劳（≥30，≤1）、`[acceptance-gate]` 验收失败（≤2，附输出尾巴）、`[continue]` C3 预算续跑（≤3 轮，列未完成项）、thinking 重试、`[budget]` 预算预告（G8-1，volatile 不持久）。 | `core/turn_policy.py:236-410,336-369`
- **SOP 系（tail）**：技能推荐/软硬干预、F1 错误恢复缓存（`<error-recovery>`）、F2 阶段、F3 模式。 | `request_assembly.py:201-250`
- **steering**：用户中途输入 → `[steering]` 行 + checkpoint。 | `agent_loop.py:865-881`
- **台账已退役**：`ledger-gate` 在 T6/`da9e33e` 退役（保留 `LedgerUpdated` 观测）；`turn_policy.py:377` 注释"the ledger gate's nudge"是**残迹**（观察项，建议清理）。
- 对照：dsh=pre-step 8 类注入 + 工具后 additionalContexts（重复调用提醒/目标收尾/job 通知）+ goal round prompt；opencode=steer/synthetic 续写/`MAX_STEPS_PROMPT`/checkpoint 注入。**干预密度三家最高，但全部是现象修补（fatigue 补"转圈"、strategy 补"卡死"）而非结构。**

## 5. 外部化思考（写进上下文给自己看）

- `todo_write`（进 tail 每迭代）；`checkpoint_write` → digest note（R8a）；digests ring（压缩后才注入的 working memory）；memory harvest → notes（跨回合）；acceptance（机械契约）；I3 压缩前锚点块；`_current_instruction` 压缩钉住。
- 对照：dsh=todo 不进请求 / plan 模式 / goal / 八段 checkpoint；opencode=无 todo、七段 checkpoint、`/btw` 侧问。

## 6. 回答的收束

- 正常：最后一步 text 即答案（COMPLETED）。
- 预算死而活未完：C3 续跑耗尽后 → **`_ask_for_closing`**（G8-2：一次有界"收尾词"调用）→ 仍无话 → **`render_handoff`**（把任务/产物/失败/续跑计写成用户可读交接）。
- 截断：`truncated_by_length` 只在结果里标记，**不自动续写**（与两家一致）。
- 对照：dsh 无 closing 提示（UI 取最后非空 assistant，诚实）；opencode `MAX_STEPS_PROMPT`（assistant 角色 + 禁用工具逼答）。**我们的收束机制三家最完整。**

## 7. 跨压缩的思考持久化

- 七段 checkpoint：`## 目标 / 约束与要求 / 决策 / 工作状态 / 下一步 / 关键文件 / 重要上下文`（合并更新、形状校验、r15 收缩阶梯、断路器——详见 11-plan §7.3 勘误）。 | `ai/llm_helpers.py:145-153`
- digest ring 只在压缩后注入；压缩前锚点（I3）。三家模板收敛（我们=opencode 七段≈同构；dsh 八段）。

## 8. 总评

**强**：干预密度与机械验收三家最高；thinking-only 防线三家独有；推理展示链路（捕获→Thought 行→落库）完整；收束（closing+handoff）最完整。
**弱（真缺口，按重要性）**：
1. **静态认知提示近零**——"怎么思考"的第一层（工具方法论）缺失，全靠 schema description 自己悟；
2. 干预全是**提示词补丁**（fatigue/strategy 是现象修补）——这是"目光短浅"在认知层的实体；
3. reasoning 单向下行——对 DeepSeek 正确，但对支持 thinking replay 的 provider 是未开发面；
4. 台账退役残迹（`turn_policy.py:377` 注释）等待清理。
