## 2. 审计：上一版方案（14 号稿 v1）的三处错误

> 本稿是 v2。v1 的错误记录在此，因为它们改变设计，不是措辞问题。

| # | v1 的写法 | 错在哪 | v2 的写法 |
|---|---|---|---|
| **E1** | 「层间更具体的一层先说话，层内 findLast」 | **多造了一个机制**。OC 的 findLast over 拼接层序**同时**满足「层内后写优先」和「层间后层覆盖前层」。v1 那套要额外写「逐层找 + 第一个说话者赢」，且与 findLast 混用时行为难解释 | **层序 = 拼接顺序，一个 findLast**（§4.2.2） |
| **E2** | 把 `config.local.yaml` 的 mcp 权限 / trusted / skill 策略**翻译成规则**，放在最不具体的一层 | ① 翻译后 config-deny 从「绝对」变成「最不具体」，能被项目文件覆盖 = **安全倒退**；② trusted 要译成 `server__*` 通配、skill 要引 resolver，都是新代码路径；③ skill deny 今天绝对压过 allow-list，翻译后不再绝对 | **只译 config-allow 与 trusted**（它们需要能被规则覆盖）；**config-deny 与 skill 策略留在 gate 硬拒层**（§4.2.1） |

## 4. 逐文件详设

### 4.1 `ai_coding/security/permissions.py`（新建）

> 目标：**一个能独立测试的规则语言**。它不认识 gate、不认识 dispatch、不认识配置——只回答一个问题：`(action, subject)` 这件事，允许吗？

#### 4.1.1 数据结构

```python
class Effect(enum.Enum):
    ALLOW = "allow"
    ASK = "ask"
    DENY = "deny"

@dataclass(frozen=True)
class Rule:
    action: str
    resource: str
    effect: Effect
    reason: str = ""

Ruleset = Sequence[Rule]
```

`Effect` 与 gate 现有的 `PermissionDecision`（ALLOW/WARN/DENY）**是两个不同的东西**：`Effect` 是规则语言的三态，`PermissionDecision` 是 gate 的判决。映射只有一处（`ASK → WARN`，§4.2.3）。不合并：合并会让 `PermissionDecision` 多一个成员，触及全仓几十处断言。

#### 4.1.2 base 规则（今天的档位逐条翻译）

```python

#: proof (a test asserts 21 + 3), because a base that drifts from the
```

> ⚠️ `mcp_call` 在 base 里是**兜底中的兜底**：MCP 工具实际以 `server__tool` 为 action（`tools/mcp_call.py:66`），真正的 MCP 授权走 L1 的常驻层。

#### 4.1.3 三个查询函数

```python
def matches(pattern: str, value: str) -> bool:
    """`*` matches any run of characters, crossing `/`; `?` matches one.

    Everything else in the pattern is literal: the pattern is escaped
    before the wildcards are substituted, so a rule written for a path
    cannot smuggle a regular expression in.
    """


def evaluate(action: str, subject: str, *layers: Ruleset) -> Rule | None:
    """The last matching rule across the layers; ``None`` when none match.

    The layers are concatenated in the order given and the last match
    wins -- so a later layer overrides an earlier one, and within a layer
    the later line wins.  That is what lets one layer say "edit * deny"
    and then open a single directory again, and it is why the layers are
    ordered by how specific they are rather than by what they contain.

    ``None`` means the rules have no opinion.  The caller decides what
    that means; for the gate it means "ask the human" (fail-closed).
    """


def wholly_disabled(action: str, *layers: Ruleset) -> bool:
    """Whether the whole action is cut from the catalogue.

    The *last* rule matching the action decides: ``* * deny`` cuts
    everything, ``edit * deny`` followed by ``edit <dir>/* allow`` does
    not -- the tool stays visible and the refusal happens at dispatch,
    where the model can read what it hit.
    """
```

`evaluate` 与 `wholly_disabled` 都吃**同一批层**——这是 I1 的结构保证：目录裁剪与执行判定不是「两套谓词碰巧一致」，而是「同一个函数、同一个输入的两次查询」。

#### 4.1.4 资源（subject）是什么

```python
def subject_of(action: str, params: Mapping[str, Any]) -> str:
    """The concrete thing the call acts on -- what a rule's resource matches."""
```

| action | subject |
|---|---|
| `read` / `write` / `edit` | `params["path"]` 归一化 |
| `glob` | `params["pattern"]` 归一化 |
| `grep` | `params["pattern"]` 归一化（`path` 是可选的搜索根，不是被碰的东西） |
| `bash` | `params["command"]` |
| 其他（含 `server__tool`） | action 本身 |

> `read` 的 subject 是**文件**（不是目录）。目录粒度是 saved 的事（§4.4），规则匹配要精确到文件。
> 归一化只做词法（去 `./`、`\` → `/`），**不做解析**：`Sandbox` 才是边界的裁决者——沿用 `grant_key` 的既有立场（`permission_gate.py:318-327`）。

#### 4.1.5 规则文件

```python
def load_rules(path: Path) -> tuple[Ruleset, list[str]]:
    """Read one rules file.  A broken file yields no rules and an error.

    The error is not swallowed: a rule the operator wrote must not fail
    silently, so the caller shows it (``/permissions``) and logs it.
    """
```

文件格式（YAML，PyYAML 已在依赖里）：

```yaml
# <workspace>/permissions.yaml
rules:
  - action: edit          # 必填；支持 * 通配
    resource: "*.env"     # 必填；支持 * 与 ?，* 跨 /
    effect: deny          # 必填：allow | ask | deny
    reason: "环境变量文件不能改"   # 可选
```

- **顺序即优先级**：同一 `(action, resource)` 命中多条时，最后一条生效。
- `*` 匹配任意字符（**含 `/`**），`?` 匹配一个字符；**不支持 `**`**（`*` 已跨 `/`，`**` 无语义）。
- 坏文件 / 坏条目 → **跳过 + 记错误**，不崩、不静默（错误出现在 `/permissions` 的输出与日志里）。
- `reason` 可选：没有就用生成的文案（`denied by rule: edit *.env`）。

#### 4.2.3 `check()` 的新形状

```python
def check(self, tool_name: str, params: dict[str, Any], *, session_id: str = "") -> Decision:
    """Return a ``Decision`` for the given tool invocation.

    Three layers answer, in this order.  The *hard denials* (a red line,
    a tool the config refuses, a skill the policy refuses) are final:
    no rule can reopen them.  The *rules* then answer: the last matching
    rule across the layers, and a rule that denies is final too, so a
    standing grant cannot reopen it either.  Only then does the *saved*
    layer get its say -- it holds standing allows, so it can lift a
    question but never a refusal.
    """
    name = tool_name.lower()
    action = name
    subject = subject_of(action, params)

    # 1. bash hard-deny -- the red lines are a gate-layer rule, above the
    #    rules: a rule's allow never reopens a red line (I3).
    if action == "bash":
        reason = bash_denied(str(params.get("command", "")))
        if reason:
            return Decision(PermissionDecision.DENY, f"bash command blocked: {reason}",
                            action=action, resource=subject)

    # 2. a tool the operator's own config refuses outright.
    if tool_name in self._denied_tools:
        return Decision(PermissionDecision.DENY,
                        f"tool '{tool_name}' is denied by configuration",
                        action=action, resource=subject)

    # 3. the skill policy, judged per skill id.
    skill = self._skill_decision(action, params)
    if skill is not None:
        return skill

    # 4. the rules.
    rule = evaluate(action, subject, *self._layers(session_id))
    if rule is not None and rule.effect is Effect.DENY:
        return Decision(PermissionDecision.DENY,
                        rule.reason or f"denied by rule: {rule.action} {rule.resource}",
                        action=action, resource=subject)

    # 5. a standing grant the operator gave earlier.  It can lift a
    #    question; it can never reopen a denial (I2).
    key = grant_key(name, params)
    if key is not None and key in self._grants:
        return Decision(PermissionDecision.ALLOW, "", action=action, resource=subject)

    if rule is None:
        # No rule had an opinion: ask, and say that the tool is unknown.
        return Decision(PermissionDecision.WARN,
                        f"unknown tool '{name}' requires confirmation",
                        action=action, resource=subject)

    if rule.effect is Effect.ASK:
        return Decision(PermissionDecision.WARN,
                        rule.reason or f"tool '{name}' requires confirmation",
                        action=action, resource=subject)

    # ALLOW -- but a path outside the workspace is a question, not an answer.
    outside = self._outside_resource_reason(action, params)
    if outside is not None:
        return Decision(PermissionDecision.WARN, outside, action=action, resource=subject)
    return Decision(PermissionDecision.ALLOW, "", action=action, resource=subject)
```

### 4.3 `ai_coding/core/agent_loop.py`（改）—— I1 的落点

```python

def _keeps(self, tool: BaseTool) -> bool:
    """Whether the catalogue advertises this tool at all.

    The same question the gate asks, asked the same way: the last rule
    matching the tool's action decides, and only a whole-action denial
    cuts it.  A denial that names a path leaves the tool visible, so the
```

### 4.5 `ai_coding/core/hooks.py` + `dispatch.py`（改）—— T2b 的 hook

```python
# core/hooks.py
class HookPoint(enum.Enum):
    ...
    PERMISSION_EVALUATE = "permission.evaluate"

CAPABILITIES[HookPoint.PERMISSION_EVALUATE] = frozenset({"observe", "block"})
```

**能力集里没有 `rewrite`** → hook 不能把 DENY 变 ALLOW，也不能把 ASK 变 ALLOW。它只能**收紧**。

**调用点**（`dispatch._decide`，在 gate 判定之后、审批之前）：

```python
verdict = _verdict(item.decision)
if verdict is PermissionDecision.DENY:
    return self._denied(call, reason), True, False     # deny 是终局，hook 不触发

# T2b: a hook may veto.  It may not loosen: the deny above already
# returned, and the hook's capability set has no "rewrite".
hook_decision = await self._run_hooks(
    HookPoint.PERMISSION_EVALUATE, call, ctx, turn_view,
    extra={"permission": {
        "action": item.decision.action,
        "resource": item.decision.resource,
        "effect": item.decision.decision.value,
    }},
)
if hook_decision is not None and hook_decision.decision is HookDecision.BLOCK:
    return self._hook_blocked(call, hook_decision), True, False
```

`_run_hooks` 新增一个 `extra` 关键字（`payload.update(extra)`）。

> **两条对照**：opencode 的 `permission.evaluate` hook 在 deny 短路**之后**触发（`packages/core/src/permission.ts:175` vs `:179`）→ 它放宽不了 deny；dsh 的 `ToolGuard` 更严 ——「守卫没有 allow 结果，所以 listener 顺序不能把拒绝变回允许」（`packages/core/tools/src/index.ts:724-732`）。本批取 dsh 的严格版：**hook 的能力集里没有 allow 语义**。

## 8. 最终模样推演

> 「按这个计划实施完之后，长什么样」——用来验证中途细节是否自洽。

### 8.1 一个操作员写的规则文件

```yaml
# <workspace>/permissions.yaml
rules:
  - action: edit
    resource: "*.env"
    effect: deny
    reason: "环境变量文件不能改"
  - action: bash
    resource: "rm -rf *"
    effect: deny
    reason: "递归删除要先问人"
```

### 8.2 模型调用 `edit .env` 的完整判定

```
action  = "edit"
subject = ".env" → 归一化 → "env"      ← 等等：".env" 去 "./" 不变，仍是 ".env"

evaluate("edit", ".env", L0, L1, L2, L3, L4):
  L0: Rule("edit","*",ASK)      命中 → found = ASK
  L1: 无
  L2: 无
  L3: Rule("edit","*.env",DENY) 命中 → found = DENY
  L4: 无
  → found.effect = DENY
check():
  1 bash 红线：不是 bash，跳过
  2 config deny：不在名单
  3 skill 策略：不是 skill
  4 found.effect 是 DENY → return Decision(DENY, "环境变量文件不能改")
  5 saved：没走到
→ 模型看到："环境变量文件不能改"
```

> ⚠️ **发现一个细节问题**：`subject_of` 对 `.env` 的归一化 —— 去 `./` 前缀不适用（`.env` 不是 `./env`），但 `matches("*.env", ".env")` 呢？`*` 匹配空串 + 任意 → `.env` 以 `.env` 结尾 ✓ 命中。
> 而 `matches("*.env", "a/b/.env")` → `*` 跨 `/` → ✓ 命中。
> **但** `matches("*.env", "env")` → 不命中 ✓（`.env` 要求有点）。
> ✓ 语义正确。

### 8.3 模型调用 `bash rm -rf /tmp/x` 的完整判定

```
action = "bash", subject = "rm -rf /tmp/x"
1. bash_denied("rm -rf /tmp/x") → ""（W4 的规则：目标非系统目录 → 不拦）
4. evaluate("bash", "rm -rf /tmp/x", L0..L4):
     L0: Rule("bash","*",ASK)  → found = ASK（reason "bash command requires confirmation"）
     L3: Rule("bash","rm -rf *",DENY) → 命中？matches("rm -rf *", "rm -rf /tmp/x")
         → "rm -rf " 字面 + "*" 匹配 "/tmp/x" ✓ → found = DENY
4. found.effect = DENY → Decision(DENY, "递归删除要先问人")
```
> 规则文件把一条**具体形态**禁掉了，而 base 的 `bash * ask` 仍在（不冲突：findLast 取最后的 DENY）。
> 注意这与 W4 的 `bash_redlines.py` 是**两套**：红线拦的是「危险目标」，规则文件拦的是「团队不想看到的形态」。红线的 deny 在更上层 → 红线仍然优先 ✓。

**新能力按设计工作**：

| 场景 | 无规则文件 | 有规则文件 |
|---|---|---|
| `edit .env` | ASK | **DENY**（"环境变量文件不能改"） |

## 12. 调研结论：设计稿与实证的冲突

> 三处冲突全部经源码验证。08 是机制设计权威稿，但**事实层以源码为准**；本批只修正事实层，不改 08 的机制取向。

| # | 08 的写法 | 源码实证 | 本批的处理 |
|---|---|---|---|
| **①** | T2c「`always` 保存**实际** `(action,resource)`（不是工具传入的 `save`）」被列为 **parity** 项 | opencode 存的**就是** `save`：`saved.add({action, resources: existing.request.save})`（`packages/core/src/permission.ts:299-305`）；edit/read 的 save 是 `["*"]` = 所有路径 | **定性改为「超越 opencode 的主动改进」**，不进 parity 账。实现保留 08 的口径（本仓今天已是实际资源） |
| **②** | T2b/T2c 的 deny 优先级只说「deny 必须先于 saved」（C12） | opencode 的 deny 短路在 hook **之前**（`packages/core/src/permission.ts:175` vs `:179`）→ hook 放宽不了 deny；dsh 的 `ToolGuard` 更严：「守卫没有 allow 结果，所以 listener 顺序不能把拒绝变回允许」（`packages/core/tools/src/index.ts:724-732`） | **写进契约**：hook 能力集只有 {observe, block}，deny 短路在 hook 之前（§4.5） |
| **③** | T2「新增 base `* * allow`」 | 今天 read/glob/grep **免审批**（`_allow_tools`），改 base 会改变 read 的工作区外行为 | **base = 今天的两张名单逐条翻译**（24 条），无兜底规则；「无匹配」由 gate 显式处理成 ask（§4.1.2、§4.2.3） |

**dsh 的两条相关发现**（05 底稿未覆盖，本次源码验证）：

| # | 发现 | 对本批的意义 |
|---|---|---|
| 1 | dsh **没有** `{action,resource,effect}` 规则表，也没有 always-allow 记忆（`packages/interaction/user-approval/README.md:154` 明写 "no `allow-always`, remembered rule, revocation, or grant store"） | **T2/T2c 的规则引擎是纯自研**，不能指望从 dsh 抄。dsh 值得抄的只有**扩展点形状**（单调守卫、`never` 在 service 内部决定）→ 已落进 §4.5 的 hook 纪律 |
