### 3.2 路径候选判别式（拍板①的实现）

**问题**：`outside_workspace_paths` 的候选提取靠 `_OUTSIDE_PATH_RE`（`plan_runner.py:95-97`）硬编码 11 个根白名单，`/data/x`、`/workspace/y` 实测**扫不出**（08 §7.2 R02 验收明确要求这两个）。

**问题 2**：直接换成通用匹配会误伤 API 路由。实测（`/tmp/opencode/probe4.py`）`Sandbox.resolve("/api/v1/users")` 同样抛 `SandboxViolation`——**resolve 只判可达性，不判「这串字符是不是文件系统路径」**。所以通用候选必须配一道判别式。

**解法（两层，缺一不可）**：

```python
# 第一层：候选提取 —— 通用绝对路径，去掉根白名单
_OUTSIDE_PATH_RE = re.compile(r"(?<![\w:./])(?:/[^/\s'\"`,;)\]]+){2,}")

# 第二层：判别式 —— 这串字符像不像文件系统路径
def _looks_like_path(candidate: str) -> bool:
    # (a) 末段命中本仓既有的文件扩展名契约（file_mentions.py 的白名单）
    if candidate.rsplit("/", 1)[-1].lower().endswith(FILE_PATH_EXTENSIONS):
        return True
    # (b) 首段是本机真实存在的目录
    return Path("/" + candidate.split("/")[1]).is_dir()
```

- **(a) 复用 `file_mentions.py:31-40` 的扩展名白名单**（`(?:py|md|txt|json|ya?ml|ts|tsx|js|...|ipynb)`）——这正是本仓自己认定的「什么像文件路径」（该文件注释明写：这是把 `main.py` 与同形散文区分开的依据）。**不造轮子**。
  - **提取形态注意**：白名单在 `_BARE_PATH` 里是**正则片段** `(?:py|md|...)`（`file_mentions.py:32-35`），不是 `|py|md|`。提取为公共常量时须保持正则片段形态（`_BARE_PATH` 用它拼正则；判别式用它拼一个 `endswith` 的 alternation：`re.compile(r"(?:" + FILE_PATH_EXTENSIONS + r")$", re.IGNORECASE)`）。**不能**改成 `|py|md|` 形态——那样 `endswith` 用不了。
- **(b) 首段真实目录**：覆盖 `/home/...`、`/etc/passwd`、`/usr/local/bin/...`（无扩展名但确为文件路径）。
- **URL 排除沿用 `file_mentions.py:41-44` 的 `_URL_PREFIX` + `_URL_LOOKBEHIND` 契约**（`https://x.dev/home/a/b` 不得被当成路径）——`(?<![\w:./])` 已排除 `//` 后的斜杠，再用 URL 前缀 lookbehind 双保险。
- **相对路径排除**：`(?<![\w:./])` 使 `../sibling/file.py`、`./config/settings.yaml` 不会被误抓（`/` 前是 `.`）。

**实测对照**（14 例，判别后仅 1 例不符）：

| 文本 | 期望 | 通用候选 | 判别后 |
|---|---|---|---|
| `把项目建到 /home/x/y` | 拦 | ✓ | ✓ |
| `GET /api/v1/users 返回用户列表` | 不拦 | ✓误伤 | **不拦** |
| `新增 POST /api/v1/orders 接口` | 不拦 | ✓误伤 | **不拦** |
| `参考 https://x.dev/home/a/b 文档` | 不拦 | 不抓 | 不抓 |
| `从 ../sibling/file.py 导入` | 不拦 | 不抓 | 不抓 |
| `编辑 ./config/settings.yaml` | 不拦 | 不抓 | 不抓 |
| `写入 /data/x/app.py` | 拦 | ✓ | ✓ |
| `另见 /etc/passwd` | 拦 | ✓ | ✓（首段 /etc 存在） |
| `文件路径 /a/b 这样的` | 不拦 | ✓误伤 | **不拦**（无扩展名、/a 不存在） |
| `日期 2026/10/20 之前` | 不拦 | 不抓 | 不抓 |
| `和/或的关系` | 不拦 | 不抓 | 不抓 |
| `把工具装到 /usr/local/bin/foo` | 拦 | ✓ | ✓（首段 /usr 存在） |
| `见 /home/.../awesome-tool-kit/hotel` | 拦 | ✓ | ✓（首段 /home 存在） |
| `部署到 /workspace/y` | 拦 | ✓ | **漏**（首段 /workspace 本机不存在） |

**已知残余（必须登记）**：`/workspace/y` 这类「首段本机不存在 **且** 末段无已知扩展名」的路径仍漏判。取舍理由：它与 `/api/v1/users` 在结构上**完全同形**，任何不依赖本机存在性的判别式都无法分开二者——而依赖本机存在性就必然漏掉假设的挂载点。要覆盖它只能引入「路径语境词」启发式，那是无限维护项且 opencode 无对应（拍板时已明确否决）。**08 §7.2 的 R02 验收用例因此改写为 `/data/x/app.py` 形态**（仍是假设挂载点，仍验证「非白名单根」这条根因），`/workspace/y` 登记为残余。

### 3.4 三处统一 disarm（拍板②）

**真实时序**（核验结论，11 号稿原文有误）：`present_plan` approve 时已 `ctx.task.armed = True`（`present_plan_tool.py:254-255`）并随回合落盘；`PlanRunner.run` 顶部再 arm 一次（`plan_runner.py:297-298`）。所以「执行器门在 arm 之前」不成立——**门的作用是「撤销 arm」而非「不 arm」**。

| 位置 | 触发时机 | disarm 动作 | 持久化 |
|---|---|---|---|
| present_plan 预校验 | ask 之前，**尚未 arm** | 无需 disarm（还没 arm） | 无 |
| plan_only 门#2（`:171-173`） | 规划回合后，**已 armed** | `task.armed = False` | 需落盘 |
| PlanRunner 前置门 | arm 之后、driver 之前 | `task.armed = False` | 需落盘 |

**统一 disarm 辅助（`plan_runner.py` 内私有函数）**：

```python
def _disarm(task: Any) -> bool:
    """撤销 plan profile 的 arm；返回是否发生了变化。"""
    if not getattr(task, "armed", False):
        return False
    task.armed = False
    task.armed_profile = ""
    return True
```

> `armed_profile` 一并清空：与 `agent_loop.py:939-940` 的 dismiss 分支同语义（`task.armed = False; task.armed_profile = ""`）。

**落盘**：`plan_only` 与 `PlanRunner` 都通过 `self._persist(session)`（`plan_runner.py:439-450`，走 `loop.closer.save`）。`plan_only` 是模块级函数不是方法 → 改用 `getattr(getattr(loop, "closer", None), "save", None)`，与 `_persist` 同一形状。

**事件**：disarm 发生了状态变化 → 需 `_emit_task(observer, task)`（R06 语义）。`plan_only` 有 `observer` 参数（`:144`）；`PlanRunner.run` 也有（`:286`）。

> **既有瑕疵（非本批引入）**：`plan_runner.py:323` 与 `:325` 是**两次完全相同**的 `_emit_task(observer, task)` 调用——重复事件。本批**不修**（不属本批范围），但新增的 disarm 事件不得再加第三次。实施时：执行器门自己发一次 disarm 事件，`finally` 块保持现状（两次重复事件是既有的，不叠加）。

```ts
 * Plan run eligibility, the pure half (W2/R11).
 *
 * An approved plan starts executing when its turn ends cleanly.  A turn that
 * ended aborted / error / timeout / budget / max_iterations / stopped did not
 * reach a clean end, so the run is not dispatched from it -- the approval stays
 * on the task, and the boot resume path decides what happens next.
 *
 * The turn's status arrives as wire data (server/bridge.py:184, handlers.py:504),
 * so it is untyped here; the comparison is by value.

export function shouldDispatchPlanRun(pending: boolean, status: unknown): boolean {
  return pending && status === "completed"
}
```

### 11.2 真机发现的两处修正（单元测试抓不到）

真模型（qwen3.7-flash）跑 `/plan <topic>` 产出越界计划，暴露两处：

**① 目录目标漏判**。模型写的是「确保目录 `/data/w2demo/` 存在」——**无扩展名、首段本机不存在**。原判别式（末段扩展名 OR 首段真实目录）放过它，评审卡照弹、计划照批、armed 留在盘上。单元测试用 `/data/x/app.py`（带扩展名）恰好绕过了这个洞。
**修正**：尾斜杠 + 目录语境词（目录/文件夹/创建目录/mkdir/directory/folder **紧邻**路径，中间只隔空白或引号）。语境词是必需的——`/api/v1/users/` 与 `/data/w2demo/` 结构完全同形，只看斜杠会把合法路由也拒（阻塞性误伤）。语境词「紧邻」是必需的——「目录结构如下 /api/v1/」里的「目录」是文档目录的意思。

**② shebang 解释器误伤**。拒绝信息列了三个路径：`/data/w2demo/app.py, /data/w2demo, /usr/bin/env`。第三个来自 verify 里的 shebang 行（`#!/usr/bin/env python3`）——脚本解释器，不是文件工具要写的目标。模型无从改它，于是**重试 13 次才改对**（22 拒 / 2 过）。
**修正**：shebang 豁免**它自己命名的那个**解释器路径，且只豁免那一个（按位置判断，不是「路径之前任意位置有 `#!`」——后者会让同一句里后面的真目标一起被放过）。
