> 状态：**待实施（未动码）**。开工前请用户拍板本稿（尤其 §12 sanctioned 迁移清单）。
> 依据：`08-三方对比与内化设计.md` §4.1（R03/R08/R10/R09/R04）、§6 决策（Q2=B 显式协议、评审卡必须展示 items）；前批格式与实践经验见 `09`。
> 目标一句话：**让"用户批准的内容 = 用户看到的内容 = 真正被执行的清单"，且"批准/搁置/继续改"三种意志各自只做自己该做的事。**

## 0. 目标与最终模样

W1 落成后：

1. **只有 plan 姿态能提交计划**：normal / step / goal 回合调用 `present_plan` 得到结构化 `not_in_plan` 拒绝；goal 任务在跑时 `/plan` 与 approve 都不可能劫持它（C02/C08 关门）。
2. **评审卡展示"真正要执行的东西"**：完整 plan 可滚动 + items 表格（序号 / 内容 / verify / 依赖）；批准 = 用户看过的内容（C01 关门）。
3. **计划可以有依赖**：items 支持前向 `depends_on`（0-based），批准后转成 item id，执行器按依赖选 ready（C07 关门）。
4. **提交语义严格**：只有**精确 approve**（或未来的 `finish_research`）算提交；`keep` 是带反馈的 tool error（同 turn 重做）；**dismiss（esc/空答案）= 结束本轮、不提交、不 arm、不自动执行**；"假提交+搁置"绕过守卫的路被堵死（C09 关门）。
5. **批准 = 新 episode**：旧计划的轮数/resume 计数/token 账与阶梯状态清零，新计划不背旧账（F-45 关门）。
6. **`/readonly` 不再被 plan 守卫误伤**：只读（非 plan）回合收尾不再被催交计划。

## 2. 契约与复用（先读这节，再读逐项）

### 2.1 `ToolContext.mode`（R03）

- `ToolContext` 增字段 `mode: str = "normal"`；`tool_context(...)` 从 `session.mode` 填充。

### 2.2 `ask(data=)`（R04）

- 协议：`async ask(question, options=(), *, detail="", intent="", data: dict | None = None) -> UserAnswer`。
- 实现：CLI/Unavailable 忽略 `data`；IPC `question_provider` 传 `"data": dict(data or {})`；前端 `AskRequest` 加 `data?: Record<string, unknown>`，`parseAskRequest` 只在是对象时保留。
- PresentPlanTool 传入形态（W1 冻结，W2 只加 `warnings` 键）：

```python
data = {
    "items": [
        {"content": c, "verify": v, "dependsOn": [i + 1 for i in deps]}  # 转成 1-based 展示序
        for (c, v, deps) in items
    ],
}
```

### 2.3 `TurnBooks.plan_approved` / `plan_dismissed`（R08）

- `note_outcomes` 里从 `item.result.data` 读（`ToolResult.data` 已是机器可读结果，`domain/message.py:77`）：

```python

    item.call.name == "present_plan"
    and isinstance(item.result.data, dict)
    and item.result.data.get("approved") is True
    for item in succeeded

    item.call.name == "present_plan"
    and isinstance(item.result.data, dict)
```

- 快照口径：`turn_books.py:401` 的 `plan_submitted="present_plan" in self.tool_success` **改为** `plan_submitted=self.plan_approved`。
- 双保险：`keep` 改为 `success=False`（§6），不进 `tool_success`。

### 2.4 dismiss → 回合在批次末结束（R08）

- 位置：`agent_loop.py` 主循环 `books.note_outcomes(outcomes)` 之后、现存 `if any(item.halted ...)` 旁（`:894`/`:911`）：

## 3. R03 · `present_plan` 门禁

### 3.1 现有设计（根因）
- 注册与姿态无关（`builder.py:232-237`）；`execute` 不做任何姿态/armed 检查（`present_plan_tool.py:111-190`）；approve 直接 `ctx.task.items.clear()` + `armed_profile="plan"`——normal/step/goal 都能走到这里（C02/C08）。
- `/goal` 会拒绝 plan/readonly（`commands.py:370-372`），但 `/plan` 不检查 armed goal（单向互斥）。

### 3.2 目标设计
1. `execute` 最前置：
```python
if ctx is None or getattr(ctx, "mode", "normal") != "plan":
    return ToolResult(
        success=False,
        output="present_plan 只在计划模式可用：先 /plan（或 shift+tab 切到 Plan）。",
        error="not_in_plan",
    )
```
2. armed 门（mode 之后、解析 items 之前）：
```python
task = getattr(ctx, "task", None)
if task is not None and getattr(task, "armed", False) and task.armed_profile != "plan":
    return ToolResult(
        success=False,
        output=f"目标任务（profile={task.armed_profile}）正在跑；停止后再计划。",
        error="task_busy",
    )
```
3. `/plan` 命令侧（`commands.py:_handle_plan`，`already` 判断之前）：
```python
task = getattr(session, "task", None)
if (task is not None and getattr(task, "armed", False)
        and getattr(task, "armed_profile", "") == "goal"):
    console.info("[plan] 目标任务在跑（goal）；先 /goal off 或等它结束，再进计划模式。")
    return REPLAction.CONTINUE, session
```
4. approve 分支保持 `armed_profile="plan"`（此时已保证非 goal）。

### 3.3 数据流影响
- normal/step/goal 的 `present_plan` 调用在"问人之前"被拒 → 不弹卡、不耗审批、不 arm。
- step 会话（fresh，`mode` 默认 normal）天然被拒——执行中的步骤不能再开评审。

## 6. R08 · 严格提交语义

### 6.1 现有设计
- `_HOLD`（esc/空）与 `keep` 都返回 `success=True`（`present_plan_tool.py:161-167`、`:191-197`）；`turn_books.py:401` 只看"成功调用过 present_plan"→守卫放行；dismiss 只是"模型停步"（会把 hold 文案喂给模型）。（C09）

### 6.2 目标设计
1. **严格 approve**（`_parse_answer`）：
   - JSON `{"choice":"approve"}`（无 feedback）→ approve；
   - JSON approve + 非空 feedback → **keep**（口头/带条件的同意不是批准，dsh）；
   - JSON keep+feedback → keep；纯文本 `开始执行` → approve；其余文本 → keep（CLI 兼容）。
2. **keep = tool error + 反馈**：`ToolResult(success=False, output=_KEEP.format(feedback=...) or _KEEP_NO_FEEDBACK, error="plan_keep")`；同 turn 由模型改完再交（不进 tool_success；守卫口径见 §2.3）。
3. **dismiss = 结束回合**：`not answer.answered`（esc/空答案）→ `ToolResult(success=True, output=_HOLD, data={"approved": False, "dismissed": True})` + §2.4 的回合结束；不 arm、不 auto-run、不 NUDGE（回合已在批次末结束，守卫不再被咨询）。
4. **守卫口径**：`plan_submitted=self.plan_approved`（§2.3）；`turn_policy.py:312` 的触发面从 `mode=="plan" or readonly` 收窄为**仅 `mode=="plan"` 才跑 stop guards**（readonly 仍保留"执行类门静默"这一半，见下实现形态）：

```python
if snapshot.mode == "plan" or snapshot.readonly:
    # 18 §10.5: under either posture the execution gates are silent.
    if snapshot.mode == "plan":
        for guard in self._stop_guards:
            verdict = guard.on_stop(snapshot)
            if verdict is not None:
                return verdict
    return TurnDecision(TurnAction.FINISH, "model finished")
```

5. `PLAN_NUDGE` 文案更新（仍一次机会）：把"无法以纯文本收尾"改成明确两种合法收尾——`present_plan` 提交评审 或（未来的）研究出口；dismiss 不算收尾失败（回合已结束）。

### 6.3 数据流影响
- keep → 模型收到失败与反馈 → 同 turn 重交；dismiss → 用户意志直接落地为回合结束。
- 守卫只有"真批准"才放行；"假提交+搁置"不再产生 `plan_submitted`。

### 6.4 RIPR
- **Red**：`tests/test_present_plan_tool.py::test_keep_is_a_tool_error_with_feedback`、`::test_approve_with_custom_text_is_keep`、`::test_escape_returns_dismissed`；`tests/test_turn_books.py::test_only_an_approval_counts_as_submitted`；`tests/test_plan_guard.py::test_a_dismissed_plan_does_not_nudge`（或回合即时结束断言在 loop 用例）、`::test_readonly_alone_does_not_nudge`（迁移既有两例）；`tests/test_agent_loop_react.py::test_dismiss_ends_the_turn_at_batch_end`；前端 `plan-review-render.test.tsx`：esc 文案 = dismiss。

## 8. 数据流（改前 vs 改后）

```
[改前]
normal/step/goal ──► present_plan（不限姿态，可清表劫持）
esc/空/keep ───────► success=True ──► 守卫误判"已提交"
卡：12 行 markdown；items/verify 不可见
依赖：无法表达 ──► 批准后永远无依赖
旧计划 counts/阶梯 ──► 新计划继承

[改后]
normal/step/goal ──► not_in_plan（拒绝，不弹卡）
armed goal ────────► /plan 拒绝；present_plan task_busy
plan ──► present_plan ──► 卡：滚动全文 + items 表格（verify/依赖）
   ├─ 精确 approve ──► 整表替换（依赖→id）+ arm + TaskUpdated + episode 清零
   ├─ keep(含带备注的"approve") ──► tool error + 反馈（同 turn 重做）
   └─ esc/空 ──► dismissed：回合在批次末结束、不 arm、不 auto-run、不 NUDGE
守卫：只有 plan 姿态且"真批准"才放行；/readonly 不再被催交
```

## 11. 自核（模拟走查）

1. **step 会话**：fresh `SessionData` → `mode="normal"` → step 内 `present_plan` 被拒 ✔（不误开评审）。
2. **goal 在跑**：`/plan` 被拒（§3.2-3）；若绕过命令直接调工具 → `task_busy`（§3.2-2）；approve 永远到不了 goal 的表 ✔。
3. **批准内容一致性**：`data.items` 在 `_parse_items` 之后、ask 之前构造，与 approve 写入用**同一个**三元组列表 → 卡上第 n 行 = 任务第 n 项（同序同文）✔（RIPR 直接断言）。
4. **依赖**：只前向 → 顺序 id 必已存在；批准后 `_next_ready` 生效（既有执行侧测试）；非法依赖在 ask 前拒 ✔。
5. **五条答案路径**：approve→arm；approve+备注→keep；keep→error+反馈；esc/空→dismiss 且回合结束；超时→`no_user`（既有，不 arm）✔。
6. **守卫**：dismiss 后模型不会被 nudge（回合已结束）；readonly 单独收尾不 nudge；plan 停步且未批准未研究 → NUDGE 一次 ✔。
7. **旧账**：approve 清 counts+阶梯；boot breaker 从 0 起 ✔。
8. **冗余审查**：新增只有 `mode`/`data`/两个旗标/一个 callable/schema 一字段——每一项都有消费者（工具、卡、守卫、loop 结束、episode）；无新事件、无新端点、无第二份序列化 ✔。
