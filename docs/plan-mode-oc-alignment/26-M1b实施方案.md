### 0.1 据审核结论做的两处细化（请在审查时确认，均可一行回退）

**D1（层位置前移）**：拍板⑥/⑧ 之后，agent 层放在 **base → standing → agent → user → project → session → policy**，而不是「project 与 session 之间」。
理由（这是 ⑥ 的原始文字无法同时满足的两条约束）：

| 约束 | agent 在 project 之后 | agent 在 standing 之后（本方案） |
|---|---|---|
| 操作者文件里的 deny 要能压住 agent 的 allow（例：project `read *.env deny` vs explore 的 `read * allow`） | ✗ agent 的 allow 在后面，压过项目 deny | ✓ |
| agent 的 deny 不能被 session 的 allow 重开（例：会话 `/permissions allow write` vs explore 的 `* * deny`） | ✓（靠 ⑧ 否决层） | ✓（靠 ⑧ 否决层） |
| config `allowed_tools` 不能重开 agent 的 deny | ✓（靠 ⑧） | ✓（agent 在 standing 之上） |
| T5 的 `edit .ai-coding/plan/* allow` 不会压过项目级 `edit * deny` | ✗ | ✓ |

结论：agent 规则是「该 agent 的默认收窄」，操作者的文件与 live 会话规则才是「更具体的意图」；唯一必须反向的是 agent 的 deny（⑧ 的否决层）。**agent deny 绝对、agent allow 只赢 base/standing**，这个组合同时满足上表四行。

**D2（四态语义表）**：`CANCELLED` 定义为「这次请求撤销了一个已排队的切换」，`NOOP` 定义为「目标与当前生效态相同且没有排队项」。完整判定表在 §3.4，命令层的文案随之分派。

## 3. 目标设计

### 3.1 数据模型：agent 是唯一权威

```
SessionData
  agent: str = "build"              # 新。唯一存储权威。落盘键 "agent"（非 build 才写）
  @property mode -> "plan"|"normal"  # 只读派生：is_plan_agent(self.agent) ? "plan" : "normal"
  readonly: bool = False            # 不变：独立 overlay，与 agent 正交
  pending_posture: dict|None        # 形状改 {"agent": str|None, "readonly": bool|None, "reason": str}
  agent_history: list[dict]         # 新增。{"from","to","ts","reason","at"}；非空才落盘 "agentHistory"
```

- **`mode` 不再有 field**：删除 `mode: str = "normal"`（`:327`），改为无 setter 的 property。任何 `session.mode = ...` 立即 `AttributeError`（已用 Python 实测：property 无 setter 时赋值抛错，`fields()` 不再包含 mode）。这是拍板③的落点。
- **派生规则**（一处定义）：`PLAN_AGENT_ID = "plan"`、`def is_plan_agent(agent) -> bool`，放 `domain/agents.py`；`session.py` 从它取。plan 姿态 = 当前 agent 是内置 plan agent（08 R03/T4 自己就写的是 `agent == "plan"`）。自定义 primary agent 在 M1b **不带 plan 语义**（present_plan/finish_research/plan guard 都不对它开放）；T5/T6 把 plan 语义规则化后再放开——这是显式范围边界，不是遗漏。
- **序列化**：
  - `to_dict`：`agent`（非 "build" 才写）+ `mode`（派生值，非 "normal" 才写，给迁移期的旧读者）+ `agentHistory`（非空才写）。两者都源自 agent，不可能互相矛盾。
  - `from_dict`：先读 `agent`；没有则把旧 `"mode":"plan"` 映射成 `agent="plan"`，其余 `"build"`。未知 agent 字符串**原样保留**（词表是开放的——自定义 .md），解析失败发生在使用点：catalog 找不到 → 按 build 的规则运行并在 `/agents` 报原因；派生 mode 自然回落 `normal`（fail-safe，与今天未知 mode → normal 同规则）。
  - `KNOWN_MODES` 删除（`__all__` 同步）；旧 mode 键只作为读侧回退。
- **assistant 消息的 agent**：`ChatMessage.agent: str = ""`，`compare=False`（与 `id` 同规则，避免破坏 undo/compaction 的相等性路径）；`_message_to_dict`/`_message_from_dict` 非空才写/读；`assistant_message(step, ts, agent="")`。

**新 `ai_coding/config/agents.py`（IO + 解析）**

- `load_agents(roots: Sequence[Path]) -> AgentCatalog`，`roots` 是**低 → 高优先级**：`(user agents 目录, project agents 目录)`；内置作为最低层。

### 3.3 权限链：agent 层 + deny 否决（T1 的规则半边）

### 3.4 姿态请求：四态 + durable pending（T10）

**新 `ai_coding/domain/stance.py`**

```python
class PostureResult(enum.Enum):
    COMMITTED = "committed"   # 落到了会话上（空闲路径，且目标 != 当前）
    QUEUED = "queued"         # 回合运行中，存进 pending（durable）
    CANCELLED = "cancelled"   # 这次请求撤销了一个已排队的切换
    NOOP = "noop"             # 目标 == 当前生效态，且没有排队项
```

`AgentLoop.request_posture(session, *, agent=None, readonly=None, reason="") -> PostureResult`：

```
target_agent    = agent if agent is not None else session.agent
target_readonly = readonly if readonly is not None else session.readonly
target  = (target_agent, target_readonly)
current = (session.agent, session.readonly)
pending = session.pending_posture

if turn_running:
    if target == current:
        if pending: clear_pending(); return CANCELLED     # 撤销排队中的切换
        return NOOP
    if pending and (pending["agent"], pending["readonly"]) == target:
        return QUEUED                                      # 已经在排同一件事
    set pending = {agent: target_agent, readonly: target_readonly, reason}
    mark_pending_posture(...)                          # best-effort；存的是**已解析的目标**，不是 None
    return QUEUED

# idle
if target == current:
    if pending: clear_pending(); return CANCELLED
    return NOOP
commit_posture(session, agent, readonly, reason); clear_pending()
return COMMITTED
```

**唯一的写入口** `AgentLoop.commit_posture(session, *, agent, readonly, reason)`（供三条路径共用）。它必须把 `None` 解析成当前值（`agent = agent if agent is not None else session.agent`，readonly 同），所以 `/readonly` 这种只给一个轴的请求即使被排队，落地也不会写出 `agent=None`：
1. `request_posture` 的立即分支；
2. `_apply_pending_posture`（回合 close / 下一回合入口）——pending 落地；
3. `/plan run` 的 finally 强写回（`commands.py:589-591`）与 boot 复位（`handlers.py:354-356`）。

它做四件事（顺序固定）：
- `session.agent = agent; session.readonly = readonly`；
- 若 agent 变了：append `agent_history` 行 `{from, to, ts, reason, at=len(session.messages)}`；
- 若 agent 变了：`_emit(AgentSwitched(from_agent=..., to_agent=..., reason=..., ts=...))`；
- 清 `session.pending_posture` + 删 sidecar。

**为什么 sidecar 而不是 session 字段**（拍板②）：排队发生在**回合运行中**，此时写 session 文件会跑 `TurnCloser.save → ensure_tool_pairing`，把还没写回结果的 assistant carrier 丢掉（`service/session_service.py:103-110` 对 pending-approval 的注释就是这条已验证的教训）。sidecar 写不碰 session 文件，保存节奏不变。

**`SessionService` 新增**（与 pending-approval 同型，`service/session_service.py:112-146`）：
- `mark_pending_posture(session_id, payload|None)`：原子写/删 `<root>/pending-posture/<id>.json`；`OSError` 只吞掉（「append 失败不阻塞 turn、pending 保留」——内存里仍在，进程内照常应用）。
- `_read_pending_posture(session_id)`；`load()` 回填 `session.pending_posture`（与 `pending_approval` 同一行位置，`:179`）。
- `delete()` 一并清掉（`:235-246`，但**要放在「session 文件不存在就提前 return」之前**，见 §4.1）。

**边界语义**：提交点是回合边界（turn close 之前 / 下一回合入口），沿用现有 `_apply_pending_posture` 的两个调用点，不新造「pre-step」概念。回合进行中只排队，不改当前回合的请求（agent 在一回合内恒定）。

**命令层文案**（`app/commands.py` 4 个调用点改为 `is` 比较）：

| 结果 | `/plan` / `/agents <id>` | `/readonly on/off` |
|---|---|---|
| COMMITTED | 现有「已进入计划模式（只读）…」 | 现有「只读已开启/关闭」 |
| QUEUED | 现有「已排队…回合结束后生效」 | 同左 |
| CANCELLED | 「已撤销排队中的切换」 | 同左 |
| NOOP | 「已经是这个状态」 | 同左 |

**`/plan` 的映射**（agent 权威之后）：
- `/plan [topic]` → `request_posture(agent="plan", readonly=True, reason="/plan")`；
- `/plan off` → `request_posture(agent="build", readonly=False, reason="/plan off")`。**语义**：`/plan off` 一律回 build（04 T1 的「`/plan off` 回 build」），自定义 primary 上的用户要回自己的 agent 请用 `/agents <id>`；

## 5. 数据流

### 5.1 一次 `/agents reviewer`（自定义 primary，回合空闲）

```
commands._handle_agents
  → loop.request_posture(session, agent="reviewer", readonly=False, reason="/agents reviewer")
      target=(reviewer,False) != current=(build,False) 且 turn_running=False
      → commit_posture: session.agent="reviewer"; readonly=False
                        agent_history += {from:"build",to:"reviewer",ts,reason,at:len(messages)}
                        _emit(AgentSwitched) → bridge → wire "agent.switched" → 前端 notice
                        pending=None; 删 sidecar
      → PostureResult.COMMITTED
  → 命令层保存 session（_save_session）
```

下一次请求：`_agent_rules` = reviewer 的规则 → `tool_context(agent_rules=...)` → `gate.check`: agent 否决（write/edit/bash…）→ 目录 `hides` 同步剪掉；prompt 追加 explore 的 body；`session.mode` 仍 `"normal"`（非 plan）。

### 5.2 一次回合中的 `/plan`（排队 + 崩溃恢复）

```
回合进行中：request_posture(agent="plan", readonly=True, reason="/plan")
  → target != current → pending={agent:"plan",readonly:True,reason:"/plan"}
    + SessionService.mark_pending_posture(id, pending)   # sidecar，不写 session 文件
  → PostureResult.QUEUED

（进程被杀）

重启 load：SessionData.from_dict（agent 仍 build）
  SessionService.load → pending_posture = _read_pending_posture(id)   # 恢复排队
下一回合入口 / 上一回合 close：_apply_pending_posture
  → commit_posture(plan, True, "/plan") → agent 落盘 + 历史 + 事件 + 删 sidecar
```

### 5.3 一次带 explore 目标的子代理

```
SubAgentTool(agent="explore")
  → runner.run(..., agent="explore")
      resolve("explore") → kind=subagent ✓
      child = SessionData(agent="explore", ...)
      child_loop = AgentLoop(agents=catalog, session_permissions=parent.permissions, ...)
  → 子请求：_agent_rules(child) = explore 规则
      gate: agent 否决 → write/edit/bash 被拒；目录里根本没有它们
           父 session 规则仍继承（例如父会话 read .env deny 仍生效）
```

### 5.4 改前 vs 改后（姿态三事实）

| 事实 | 改前 | 改后 |
|---|---|---|
| 谁是权威 | `session.mode`（normal/plan）+ `readonly` | `session.agent` + `readonly` |
| plan 从哪来 | mode 字段 | `agent == "plan"`（派生） |
| 排队落哪 | 内存 `pending_posture`（崩溃丢） | 内存 + `<sessions>/pending-posture/<id>.json` |
| 返回值 | bool | 四态枚举 |
| 切 agent 的入口 | 无（只有 /plan） | `/plan` + `/agents <id>` + `default_agent` |
