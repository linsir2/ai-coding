## 1. 为什么是这三项

### 1.1 调研：oc 与 dsh 都没有这个机制

| | 规划期预算 | 触顶时怎么办 |

### 1.2 生产证据：截图那次（会话 `135cc71c`，trace `.ai-coding/traces/135cc71c…/turn-1.jsonl`）

| 事实 | 数 | 出处 |

| 交出口了吗 | ❌ 19 轮、41 次工具调用，**一次出口都没有** | trace + 会话 JSON |

**(a) 出口要得太晚** —— 模型已经用纯文本收尾，才被追着要工具出口；
**(b) 出口被预置错了** —— `PLAN_PROMPT` 的首句就是「Create a detailed implementation plan for: {topic}」，对研究型请求**指令本身命令它写计划**；`<plan-mode>` 块首句「Every request is answered with a plan」进一步加固 ⇒ 19 轮后它交的是「探索计划」⇒ 撞门。

### 1.3 真机 wire 的三个数（`scripts/plan_lifecycle_live_check.py` 留的全量 JSONL）

| 场景 | 结果 |
|---|---|
| **swap**（好模型） | 轮1 `glob+glob` → 轮2 `read` → 轮3 `glob` → **轮4 `present_plan`** ⇒ **4 轮交出口** |
| **note**（人为把 `present_plan` 从工具表拿掉） | **15 轮乱试**：模型误以为「plan mode 已退出」⇒ 调 `write`/`start_goal` ⇒ 再被只读门拒 ⇒ 一路乱试到预算耗尽 |
| 生产会话 | 19 轮探索 ⇒ 0 出口 |

⇒ **预算必须 ≥ 好模型需要的量（4–6 轮），且远小于失控时的量（15–19 轮）** ⇒ 拍板 **N = 16**。

## 3. 现有设计 → 本批设计（逐条：复用什么 / 为什么）

### 3.1 探索预算：复用已有的轮数旋钮

- **现状**：`plan_runner.py:64` 的 `PLANNING_MAX_ITERATIONS = 30`，只经由 `continuations_disabled(loop, max_iterations=…)`（`:398`）作用于规划回合。**它本来就是规划回合的独立上界** —— 只是没人管它的值，也没人告诉模型。
- **本批**：把它明确成「探索预算」，值 = **16**（拍板，§1.3）。
- **为什么不是新造一个预算类型**：新造就要新字段、新快照项、新 mouth、新记账 ⇒ 四份重复。已有的旋钮就是这个东西，只是缺一个「预算将尽」的信号。

### 3.2 提前 nudge：复用守卫的文案与记账

- **落点**：`TurnPolicy.decide_next_iteration`（`turn_policy.py:309`）—— 每轮开始前的裁决缝，loop 在 `agent_loop.py:664` 调它。
- **判据**：`snapshot.mode == "plan"`（快照里已有，`agent_loop.py:656-663` 注入）＋ `not snapshot.plan_nudged`（快照里已有）＋ `0 < max_iterations - iteration <= PLAN_WRAPUP_ROUNDS`。
- **返回**：`TurnDecision(TurnAction.NUDGE, "plan unsubmitted", inject=PLAN_NUDGE)`。
  - **为什么复用 reason `"plan unsubmitted"`**：`agent_loop.py:729` 的记账分支按 reason 匹配 ⇒ 自动 `books.note_plan_nudge()` ⇒ `plan_nudged = True` ⇒ **零新记账**，且守卫此后**不再二次 nudge**（`turn_policy.py:269`）⇒ **模型最多被问一次**（18 号稿「同一套记账，不重复」）。
  - **为什么复用 `PLAN_NUDGE`**：它已经**同时给两个出口**（`present_plan` **或** `finish_research`，`turn_policy.py:52-56`）⇒ 不另造文案，也不必为「研究型请求」单开一条路。
- **为什么放在 iteration 检查之前**：触顶那轮走 `_finish_at(…, "iteration", …)` ⇒ 守卫接管 ⇒ 提前 nudge 必须先于触顶发出。顺序不可反。
- **落点只有一处**：`/plan <topic>` 与 plan 模式发言同路径 ⇒ 同一预算、同一 nudge。

### 3.3 触顶后：走既有 A4 路径，一行不改

`plan_runner` 触顶 ⇒ `turn_policy.py:386` 的 `_finish_at(snapshot, "iteration", …)` ⇒ 守卫被问 ⇒ `plan_nudged` 为真 ⇒ `TurnDecision(FINISH, "plan unsubmitted", note=PLAN_UNSUBMITTED_NOTE)` ⇒ 回合带 note 结束 ⇒ **CLI 打印**（批次 4a 的 `commands.py:119,627`）⇒ 用户可「继续对话让它提交」⇒ **不是死路**。

### 3.4 判据前置：把「要改 / 不用改」放到两条出口前面

- **现状（两处都有同一个毛病）**：
  - `plan_runner.py:78` 的 `PLAN_PROMPT` 首句：「**Create a detailed implementation plan for:** {topic}. Break it down into specific, actionable steps. Submit the plan with present_plan: …」⇒ 对研究型请求，**指令本身命令它写计划**。
  - `ai/prompt.py:129` 的 `<plan-mode>` 块首句：「**Every request is answered with a plan**, never with the finished work: …」⇒ 同样把出口预置成「计划」；`finish_research` 的例外条款在第三段。
- **本批**：两处都改成 **判据先、出口后**：
  1. 「要改（implement / modify / add / fix / refactor）⇒ 计划」
  2. 「不用改（survey / analysis / comparison）⇒ 结论」
  3. 再给两条出口各自的用法。
- **约束**：`tests/test_plan_mode_turn.py:136` 断言指令里有「Create a detailed implementation plan」⇒ ⇒ **那个短语必须保留**，只是**挪进「要改」那一支** ⇒ ⇒ 该测试**不用改**。
- `tests/test_prompt.py:62` 的 `PLAN_SEGMENT` 是**逐字复制整个块** ⇒ 改文案必然打破它 ⇒ ⇒ **把它换成语义断言**（块在、两条出口都在、判据句在出口句之前）⇒ ⇒ 这是**加强**不是削弱：钉住的是「判据在前」这个性质，而不是散文。

## 4. 数据流的影响

```
规划回合（/plan <topic> 或 plan 模式下的人类发言 —— 同一条路径）
  │
  ├─ continuations_disabled(loop, max_iterations=PLANNING_MAX_ITERATIONS=16)   ← 探索预算（唯一旋钮）
  │
  └─ 每轮开始 → TurnPolicy.decide_next_iteration(snapshot)
       │
       ├─ [本批新增] mode=="plan" && !plan_nudged && 0 < 16-iteration <= 3
       │     └─ TurnDecision(NUDGE, reason="plan unsubmitted", inject=PLAN_NUDGE)
       │           └─ agent_loop.py:729 → books.note_plan_nudge()        ← 复用守卫的记账
       │                 └─ session.add_message(user_message(PLAN_NUDGE, synthetic=True))
       │           └─ 下一轮：模型手里有料 → present_plan 或 finish_research
       │
       ├─ iteration > 16（触顶）→ _finish_at(…, "iteration", …) → 守卫被问
       │     └─ plan_nudged=True → FINISH + note=PLAN_UNSUBMITTED_NOTE   ← A4 已有，一行不改
       │           └─ CLI 打印（commands.py:119/627）+ 前端 notice          ← 批次 4a 已做
       │
       └─ 模型自己停 → decide_after_step → 守卫 → NUDGE(PLAN_NUDGE) 或 FINISH+note   ← 全不改

每一轮请求装配
  └─ <plan-mode> 块：判据前置（present_plan / finish_research 并列，判据在前）  ← 本批改文案
```

## 8. 自核

- **零新概念**：预算 = 已有的 `PLANNING_MAX_ITERATIONS`；nudge = 已有的 `PLAN_NUDGE`；记账 = 已有的 `note_plan_nudge`；触顶 = 已有的 `_finish_at("iteration")` ⇒ **没有第二套预算、第二个 mouth、第二条记账**。
- **不碰 A4**：守卫的四条 FINISH 口、`DEAD_BUDGET_PATHS`、`PLAN_UNSUBMITTED_NOTE` 一行不改。
- **不碰非规划回合**：判据含 `mode == "plan"`，且预算旋钮只经 `continuations_disabled` 作用于规划回合。
- **单测断言不被削弱**：唯一被改的测试（`test_prompt.py`）从**逐字复制**换成**语义断言**（判据在前）⇒ 加强。
- **真机可验**：R8 需要真模型跑一轮规划回合，看第 13 轮是否出现 `PLAN_NUDGE` 且回合有出口。

## 9. 非目标

- **门拒后的乱试**（模型被拒后以为「plan mode 已退出」⇒ 去调 `write`/`start_goal` ⇒ 再被拒 ⇒ 连环乱试；真机 wire 里 15 轮、生产会话里同样）：**本批不处理**。正确的修法取决于「被拒后模型该收到什么上下文」，需要单独的真机复现 ⇒ 登记为新待办。
- **探索预算落盘 / 跨回合**：预算是回合内的，不跨回合。
- **按工具类型分预算**（读 vs 搜）：一个总数够用。
- **M1a 权限层 / M1b agent 承载** —— 与本批无关。
