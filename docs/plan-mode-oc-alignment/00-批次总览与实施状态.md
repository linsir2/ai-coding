## 3. 工作方式（每批通用；从 09 的实践固化）

1. **方案先行**：每批先按 `09` 的格式写实施文档（目标与最终模样 / 受影响面 / 契约与复用 / 逐项详设 / 数据流 / RIPR 用例总表 / 实施顺序与提交切片 / 自核 / 非目标），明确到 `file:line` 与 `test::name`；说不清或冗余的项直接砍（记录理由）。
2. **TDD / RIPR 缺一不可**：每项先写 **Red** 用例（先失败）→ 最小 **Implement** → **Prove**（目标套件转绿）→ **Regression**（全量 + 真机）。行为按设计改变的既有用例，列入"sanctioned 迁移"并随改。
3. **每项一提交**，提交信息写清"旧事实 → 新事实 → 影响"。
4. **门禁**：`python -m pytest -q`（基线以当次为准）→ `ruff check ai_coding tests` → `mypy ai_coding`；涉前端加 `cd frontend && bun test`；M2 起加真机场景（脚本放 `/tmp/opencode/plan-oc-*/`）。
5. **已知 flaky**：全量跑偶发单个 IPC/bash 时序用例超时（隔离重跑必过、回跑全量即绿），与本改造无关；处置=回跑确认，不修测试。
