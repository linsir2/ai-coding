## 1. 设计冻结（决议 → 具体设计；★ = 审核可改）

### 1.1 agent 文件与发现（Q4=B）

- 发现目录：项目 `.ai-coding/agents/*.md`；用户 `~/.config/ai-coding/agents/*.md`（与 `grants.json` 同根）。
- 优先级：项目 > 用户 > 内置；**同 id 整条替换（不做字段合并）**★。
- frontmatter schema（YAML，复用 `ai_coding/config/loader.py` 的 `yaml.safe_load`）：

```yaml
id: plan                    # ★可省略，缺省 = 文件名
name: Plan
description: Read-only planning agent
mode: primary               # primary | subagent；缺省 primary
hidden: false
permissions:                # 规则语义见 §1.2；缺省 = 空（走默认 ask）
  - {action: edit, resource: "*", effect: deny}
  - {action: edit, resource: ".ai-coding/plan/*", effect: allow}
```

- body = agent 专属指令，装配进 system（追加节）；空 body 合法。
- 校验：YAML 解析失败、未知 `mode`/`effect`/`action` → **整条跳过**并在 `/agents` 显示原因（fail-closed，不半加载）。
- 内置四条：`build`（空权限）、`plan`（§1.6 规则）、`general` / `explore`（`mode: subagent`，子代理目标）。
- 配置：`ai.default_agent: str = "build"`、`ai.plan_strict_readonly: bool = False`（与 `plan_step_max_iterations` 同处，`config/models.py:105-112` 邻域）。

### 1.2 权限规则引擎（T2；Q1 载体）

- `Rule = {action, resource, effect}`，effect ∈ `allow|ask|deny`；**无匹配默认 ask**。
- 匹配：对 `(action, resource)` 取 `findLast`；`*` 通配任意字符（含 `/`）★。
- action 词表与别名★：

| action | 命中工具 |
|---|---|
| `edit` | write, edit |
| `shell` | bash |
| `subagent` | subAgent |
| `question` | ask_user |
| `read` | read |
| 其余 | 即工具名（glob / grep / webfetch / websearch / mcp_call / memory_search / memory_write / todo_write / present_plan / finish_research / skill / …） |

- 求值顺序（dispatch 是唯一强制点，改造 `dispatch.py:306-324`）：
  1. `PermissionGate` hard-deny（危险命令表）→ 不可被规则降级；
  2. 规则 deny → 结构化拒绝（T5 文案）；
  3. 规则 ask 或 gate WARN → 审批面板（复用 `dispatch.py:385-396`；always 落 grants）；
  4. 全部放行 → 执行。
- schema 裁剪：`agent_loop.py:344-351` 改为"按当前 agent 规则做 `wholly_disabled` 判定"（某 action 的最后一条规则为 `* deny` → 整工具从 schema 移除），**延续"裁剪谓词 = dispatch 谓词"契约**（C-04/C-13）。
- `/readonly on`（无 agent）→ 生成伪规则集（edit/shell/subagent/webfetch/websearch/mcp_call/memory_write 皆 `* deny`），行为与今天一致；旧测试原样绿。
- 红线：规则 allow **不能**绕过 gate 的 hard-deny/WARN；无审批回调环境（headless）ask 一律 fail-closed。

### 1.3 研究报告出口协议（Q2=B）★

- 新工具 `finish_research`（备选名 `conclude_research`★）：参数 `{summary: str}`（必填，收尾摘要，落转录）。
- 语义：仅 plan agent 回合有效；成功后该回合 `research_finished=True`（guard 放行）。非 plan 下调用 → 结构化拒绝。
- 可见性：build 规则含 `{action: finish_research, resource: "*", effect: deny}` → `wholly_disabled` → 在 build 的 schema 自动剪除（不新增开关）。
- 与 present_plan 的边界：有可执行步骤 → `present_plan`；纯问答/分析收尾 → `finish_research`；同回合两者皆成功时以先成功者为准。

### 1.4 提醒文本（T3，冻结草稿★）

- enter：`You are in Plan mode. Discuss with the user in the conversation; explore to answer. Do not implement changes — tell the user to switch to build for implementation. Submit executable steps with present_plan; close a research answer with finish_research. When the user explicitly asks for a plan file, write it under .ai-coding/plan/.`
- leave：`Plan mode ended — back in build. Implementation is allowed again.`
- 载体：synthetic user 消息（`user_message(..., synthetic=True)`，邻居锚点 `agent_loop.py:544/700/878`）；切换时追加；**每请求对账**：历史里最后一条 plan 提醒与当前 agent 不一致或缺失 → 在最后一条 user 消息前补挂（对齐 `plugin/plan.ts:56-74`）。
- 装配位置在**消息尾**（最后一条 user 消息前），不是 system——保 prompt cache 前缀。

### 1.5 计划目录与拒绝文案（T5；Q5）

- 目录：工作区 `.ai-coding/plan/`（沙箱内，不引入 external 例外）。
- 规则 deny 文案（替换 `dispatch.py:578-596` 现文案）：
  `Plan mode cannot modify files outside .ai-coding/plan/. Explore with read/grep/glob; write plan notes only under .ai-coding/plan/; submit executable steps with present_plan.`
- 写计划文件时按需创建父目录（write/edit 工具 precheck 内，仅限该目录）。

### 1.6 软只读与开关（Q1；T6）

- `plan_strict_readonly=False`（软，=OC）：plan 规则 = `question allow / edit * deny / edit .ai-coding/plan/* allow`；**shell/subagent/web/MCP 不设 deny**。
- `=True`（硬，=今天）：追加 `shell * deny / subagent * deny / webfetch * deny / websearch * deny / mcp_call * deny / memory_write * deny`。
- 评测前默认 `False`；默认值由 §5.3 评测回填。

### 1.7 `.env` ask（T9；Q6）

- 规则：`{action: read, resource: "*.env", effect: ask}` + `{action: read, resource: "**/.env*", effect: ask}`★（任意路径下的 `.env` 与 `.env.*`）。
- 外部路径：维持沙箱硬禁（不做 external_directory ask）。

## 2. 数据流（改前 vs 改后）

目标数据流全图见 03 §6，此处只列相对现状的 4 处差异点：

1. **请求装配**：`<plan-mode>` system 段精简为静态指导；模式约束主体改为 synthetic 提醒 + 每请求对账（T3）。
2. **工具面**：`mutates_world` 静态过滤 → agent 规则 `wholly_disabled` 裁剪（T2/T6）；软档下 plan 的 edit 仍**可见**、执行期拒并给"只能写 plan 目录"文案（T5，对齐 OC `D06/D08`）。
3. **收尾判定**：`plan_submitted` 单条件 → `plan_submitted || research_finished`（T4）；guard 只在 `agent=="plan"` 触发（`/readonly` 误伤消除）。
4. **新分支**：研究型回合不弹卡、不进执行层；计划型回合 approve→替换列表→自动 `/plan run` 全链路不变。
