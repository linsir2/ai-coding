## 1. 目标与最终模样

### 1.1 今天的样子

```
用户在 Plan 模式里打字
   │
   ├─ 前端：planPrelude() → session.command {text:"/plan"}   ← 只切姿态
   └─ 前端：submit(prompt.text) → session.prompt(原话)        ← 普通回合
                    │
                    ▼
        agent_loop.process_input(原话)      ← 没有规划指令、没有 begin_plan、预算 15
                    │
                    ▼
        模型照字面执行用户的话 → 探索 9 轮 → 直接输出答案
                    │
                    ▼
        守卫事后追讨：「不能以纯文本收尾，请立即补交」
                    │
                    ▼
        模型把「已经做过的事」伪装成步骤 → verify 造假（test -f / glob '**/*'）
                    │
                    ▼
        批准 → 执行回合把同一批文件重读一遍
```

### 1.2 本批做完的样子

```
用户在 Plan 模式里打字
   │
   └─ 后端：run_human_turn() → session.mode == "plan"
              │
              ├─ session.add_message(user_message(原话))          ← 人类的话（非 synthetic）
              ├─ loop.process_input(规划指令, synthetic=True)      ← harness 的指令
              ├─ begin_plan(topic)                                ← 换一本新账
              └─ 政策：max_iterations=30 / max_auto_continuations=0
                          │
                          ▼
              模型收到规划指令 → 探索 → present_plan → 评审卡
                          │
                          ▼
              批准 → 执行回合跑的是「还没做过的事」
```

### 1.3 三个不变量

| # | 不变量 | 今天 | 本批后 |
|---|---|---|---|
| **I1** | **Plan 模式下的每一句人类发言都是一轮规划** | ❌ 只有只读姿态 | ✅ 走 `plan_only` |
| **I2** | **转录里是用户的话，不是 harness 的规划指令** | ❌ 重开后显示 1137 字符的规划指令 | ✅ 原话在前、指令被跳过；实时与重开一致 |
| **I3** | **harness 的指令不冒充用户的话** | ⚠️ 规划指令是普通 user 消息 → 会污染 `@file` 引用重建 | ✅ 规划指令是 synthetic（仓库既有约定，`request_assembly.py:486-498`） |

## 2. 现有设计与断点在哪

### 2.1 两条路径（实测）

| | **路径 A · 规划轮**（`plan_only`） | **路径 B · 只读姿态** |
|---|---|---|
| 入口 | `/plan <topic>`（`commands.py:558`） | 裸 `/plan`（`commands.py:534`） |
| 模型收到 | `PLAN_PROMPT.format(topic)` | 用户的原话 |
| 预算 | 30（`PLANNING_MAX_ITERATIONS`） | 15（`max_tool_iterations`） |
| 任务注入 | 有（`begin_plan` → `task.goal`） | 无 |
| 用户可见？ | **不在前端补全/帮助里**（19 号稿 Q1=A） | 前端内部用（`planPrelude`） |

### 2.2 断点（这是本批要修的全部）

19 号稿 Q1=A 撤销了 `/plan <topic>` 的前端暴露，理由是 `:83` 的那句：

> `[规划轮] /plan <topic>` **或 模式行下的普通 prompt**

**但那半句从没实现**：前端把「模式行下的普通 prompt」接到了 `session.prompt`（普通回合），而不是 `plan_only`。

**代码证据**：

```typescript

const prelude = planPrelude(prompt, props.commands ?? [], props.sessionId)
if (prelude) {
  void props.client.request(prelude.method, prelude.payload)   // session.command "/plan"
    .finally(() => submit(prompt.text, prompt.images))        // ← 你的话走普通回合
}
```

```python
# ai_coding/core/plan_runner.py:348-381  plan_only 的唯一调用点
# ai_coding/app/commands.py:558
report = await plan_only(loop, session, topic=rest, ...)
```

`plan_only` 全仓只有这一个调用点 ⇒ **普通用户在 UI 上永远走不到规划轮**。

### 2.3 `IpcConsole` 自己写着契约

```python

a bare ``/plan`` enters read-only plan mode and the topic rides the command
```

**「topic rides the command line」** —— 设计假定 topic 骑在命令行上。Q1=A 把命令行从用户手里拿走，**topic 就没地方骑了**。

| 新增 | 作用 | 为什么必须有 |

| `commands.run_human_turn()` | 「人类发言 → 该跑哪种回合」的唯一判定 | 两个前门（IPC / REPL）必须同义，否则同一个输入在两条路上含义不同 —— 那正是本 bug 的形状 |

### 3.3 砍掉什么（**说不清作用就砍**）

| 砍掉 | 理由 |
|---|---|
| 前端按 `synthetic` 一刀切跳过 | 会连带隐藏 5 处既有 harness 消息（`agent_loop.py:724/794/849/902/1740`）的显示 —— 那是无关功能的行为变更 |

| 逃逸口（`/chat` 之类） | 用户已拍板「没有逃逸口」；且 19 号稿 Q1=A 刚把 plan 族从前端拿掉，不新增命令面 |

| 改 `plan_only` 的工作区门 / 预算 / 守卫 | 全部已正确，不动 |
| 改 `present_plan` 的三态 | 不在本批范围（15 号稿 §6 的 D 项，需另批拍板） |
| 规划指令里的 topic 去重 | PLAN_PROMPT 已含 topic；原话与指令各出现一次 topic 是可接受的冗余（用户的话就在上一条消息里） |

**新增常量**：

```python

#: skips a user message that carries it (see ``state/replay.ts``), so the
```

**为什么两条消息、顺序是「原话在前」**：
- 指令**必须在最后** —— 那是模型下一次生成时最近看到的东西（对照实验：指令在用户消息位才有效）。
- 原话在前 → 它是「最后一个非 synthetic 的 user 消息」→ `_extract_user_input` 拿它（`@file` 引用不丢）、压缩锚点拿它（topic 不丢）。
- 模型看到原话 + 指令（指令里含 topic）—— topic 出现两次是可接受的冗余：原话是「他说了什么」，指令里的 topic 是「要规划什么」。

**为什么 `/plan <topic>` 也走这条路**：`<topic>` 就是人话（`commands.py:449` 的 `rest`）。于是：
- 实时转录：前端回显 `/plan xxx`（命令文本）
- 重开转录：`xxx`（topic）+ 规划指令（被跳过）
- 比今天（重开显示 1137 字符的规划指令）**更好** ✓，而且两条路径同构 ✓

### 4.3 `ai_coding/app/commands.py` —— 「人类发言 → 该跑哪种回合」的唯一判定

**改动 5**：新增 `run_human_turn`。

```python
# app/commands.py（放在 handle_input 之后）
async def run_human_turn(
    loop: Any,
    session: Any,
    text: str,
    *,
    console: ConsoleSink,
    on_delta: Any = None,
    observer: Any = None,
) -> str:
    """Run one human utterance as the turn it deserves.

    In plan mode a human utterance is a *planning round* (19 §4): the
    words are the topic, the model is asked for a plan, and the plan is
    what gets reviewed.  Everywhere else it is an ordinary turn.

    One function for both front doors -- the TUI's prompt and the REPL --
    because the two drifting apart is what made plan mode a read-only
    flag instead of a planning mode: the TUI sent the words as an
    ordinary prompt, so the model answered instead of planning.
    """
    if getattr(session, "mode", "normal") != "plan":
        return await loop.process_input(
            session, text, on_delta=on_delta, observer=observer
        )
    from ai_coding.core.plan_runner import plan_only

    report = await plan_only(
        loop, session, topic=text, on_delta=on_delta, observer=observer
    )
    if report.stopped:
        console.error(f"[plan] {report.stopped}")
    return ""
```

**为什么返回空串**：规划轮的收尾文本由 `plan_only` 内部产生，但它不返回那段文本（`plan_only` 返回 `PlanReport`）。REPL 侧只拿它判「要不要画一条分隔线」（`commands.py:111-112`），空串 → 不画。与今天 `/plan <topic>` 的 REPL 行为一致（`commands.py:558` 同样丢弃返回值）✓。

**为什么 `console` 是参数**：工作区门被拒时要说人话（`commands.py:561-563` 是同一个模式：`console.error(f"[plan] {report.stopped}")`）。

## 5. 数据流（改前 / 改后）

```
                    │                     ├─ begin_plan(topic)          换新账本
                    │                     ├─ add_message(原话)          人类的话（非 synthetic）
                    │                     ├─ process_input("[plan] " + PLAN_PROMPT, synthetic=True)
                    │                     │     └─ 模型收到规划指令 → 探索 → present_plan
                    │                     ├─ 政策：30 轮 / 无自动续跑
                    │                     └─ 两道工作区门（topic / items）
                    │
                    └─ 否 → loop.process_input(原话)   ← 普通回合，一切照旧
```

### 5.3 消息流（规划轮的 history）

```
[user] 请你调研这个分支都干了些啥                        ← 原话（synthetic=False）
[user] [plan] Create a detailed implementation plan …    ← 指令（synthetic=True）
[assistant] …探索…
```

- **模型看到**：两条 user 消息，指令在最后 ✓（对照实验证明这个位置才有效）
- **`_extract_user_input` 看到**：原话 ✓（`request_assembly.py:495-498` 跳过 synthetic）
- **压缩锚点看到**：原话 ✓（`context_compression.py:708-715`）
- **前端实时看到**：原话（本地回显）✓
- **前端重开看到**：原话（`[plan] ` 分支跳过指令）✓

### 13.3 实施期的两处修正

**修正 1 · 砍掉 `process_input(synthetic=)`。**

初版给 `AgentLoop.process_input` 加了 `synthetic` 关键字，让规划指令能被标成「harness 的话」（这样 `_extract_user_input` 与压缩锚点会指向人类的话而不是指令）。

**代价被实测暴露**：`process_input` 是鸭子类型契约，全仓 **28 个测试替身**（14 个文件）都写死了签名：

```python
async def process_input(self, session, text, on_delta=None, observer=None):
```

加一个 kwarg 就要改 28 处。而且实测证明：**本批的目标（规划轮 + 转录保留原话）并不依赖它** —— 规划指令里**内嵌了 topic**，所以锚点取到指令时，topic 仍在里面，信息不丢。

⇒ **按「最小化 + 只做相关的」砍掉**：协议零增长、测试零改动、改动面从 5 个文件降到 4 个。
⇒ **留下的债**（登记，不在本批）：规划指令作为普通 user 消息入库 → `_extract_user_input`（`request_assembly.py:486-498`）取到的是指令而不是原话。信息不丢（topic 在指令里），但那份契约说的「取最后一条**人类**写的」被违反了。要彻底修需要给 `process_input` 加 `synthetic`（28 个替身同步改）。

**修正 2 · `images` 的条件传参。**

`session_prompt` 原本用 `**({"images": …} if images else {})` 条件传参 —— 因为测试的 `_FakeLoop.process_input()` 不接受 `images`。改成无条件传参会让 29 个 IPC 用例当场炸。⇒ **沿用既有的条件传参形式**（这也是那个怪写法存在的原因）。
