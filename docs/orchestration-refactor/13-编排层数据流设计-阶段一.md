## 2. 逐组件设计

### 2.1 D 干预系统（`core/interventions.py` 新建；纯模块）

**结构（全部纯函数，无 IO）**：

```python
def settle(ledger: dict, snapshot: TurnSnapshot) -> dict      # 窗口结算：pending→helped/failed
def select(snapshot: TurnSnapshot) -> InterventionDecision | None   # 选下一干预（含升级）
def record(ledger: dict, decision: InterventionDecision, at: tuple[int, int]) -> dict
```

- **快照复用 `TurnSnapshot`（不造第二个快照类——砍）**，仅新增一个字段 `intervention_ledger: Mapping[str, Any] = {}`（frozen dataclass 默认值）；`interventions.py` 对其 **TYPE_CHECKING 引用**（避免与 turn_policy 循环导入）。
- **决策面并入 TurnPolicy（单一决策面）**：`decide_next_iteration`/`decide_after_step` 内部调 `select`；`TurnDecision` 增两个字段 `intervention: str = ""`、`level: int = 0`；loop 依此 `record`/武装 guard。否决"独立引擎"备选：loop 需要重排两个决策源的优先级，改动面更大（拍板点 Q1 确认）。
- **干预表（4 门；C3 与预算压力不入表——它们无阶梯可升，保持机制原位；这是对 12 的刻意简化**）：

| id | trigger（前/后） | 阶梯（level → 效果） | 观测窗口 / helped 信号 |
|---|---|---|---|
| `strategy` | 前：failed_streak ≥ 2 或 **stall**（iteration>stall ∧ attempted>0 ∧ successful==0） | L1 注入现 [strategy-gate] 文案 → L2 注入 L2 文案 **+ guard_window 武装** → L3 注入 ask 指令 → **L4 finish_honest（理由 no-progress，含 handoff）** | L1/L2：下 2 迭代内 streak 复位=helped；L3：窗口内出现 `ask_user`=helped；窗口落空=failed→升级 |
| `fatigue` | 前：fatigue_index ≥ 阈值 | L1 注入现 [fatigue-gate] 文案 → L2 guard_window → L3 ask 指令 | L1：2 迭代内损伤增速回落=helped；L2：同 strategy；L3：同 |
| `task` | 后：open items 停留 | L1 现 [task-gate] 文案（≤2 次） → L2 ask 指令 | L1：项状态变化=helped；L2：ask_user 出现=helped；落空=交用户（FINISH "todo ladder exhausted"） |
| `acceptance` | 后：验收未过 | L1 现 [acceptance-gate] 文案（≤2 次） → L2 ask 指令 | L1：通过率变化=helped；L2：同 task；落空=FINISH "acceptance ladder exhausted" |

- **sanctioned 行为变更（明确列出）**：① **stall 并入 strategy L4**——今天 "iteration>3 且 0 成功 → 立即 FINISH"；新：先走 L1→L2→L3（约 3 个迭代的挽救），L3 落空才 L4 诚实停。② **task/acceptance 各多一级 L2 ask**——比今天多一次"逼问用户"的机会再收尾（12 §3.2 已列入）。其余门文案、C3、预算压力、死亡门**逐字保持**。
- **文案与构建函数随表迁移**：`strategy_message` / `fatigue_message` / `nudge_message` / `acceptance_message` 及 `STRATEGY_GATE_LEAD`/`FATIGUE_*`/`NUDGE_ITEM_LIMIT` 等常量迁入 `interventions.py`（**它们就是干预文本本身**，留在 policy 会让两个模块互相导入成环）；`turn_policy` 保留死亡门/C3/预算压力文本与 `inject_task`。导入方与测试随之迁移（sanctioned）。
- **账本**：`SessionData.intervention_state: dict | None`（键 `interventionState`，非空才写）。形状：

```json
{"strategy": {"level": 2, "at": [3, 5], "outcome": "pending"},
 "task":     {"level": 1, "at": [3, 7], "outcome": "helped"}}
```

- **跨回合（审核 HIGH-1 修复：三态结算）**：`settle` 区分三态——**回合末未闭合** `pending → unfinished`（下回合**同级重试**；窗口被回合边界切断 ≠ 观测失败）；**窗口内观测失败** → `failed`（升级）；**L4 触发后** → `exhausted`（**新回合 L1 重开**，审计计数保留）。进位规则：`failed → min(level+1, 4)`；`unfinished → 同级`；其它（从未触发 / helped / exhausted）→ `1`。模拟证明：`14` §1.2（修复前退化）+ 探针追加 S5/S6（修复后语义）。
- **重置边界**（Q2 已拍）：`SessionData.begin_plan`（新计划）与"items 全终态"（任务完成，settle 时检测）清空账本。
- **触发优先级（审核 MEDIUM-3 补充）**：strategy（含 stall）> fatigue > task > acceptance；同一迭代只产出**一门**的决策；`finish_honest`（L4）优先于其它门的注入——保留 `test_fatigue_system.py:208` 钉住的 "Stall takes precedence over fatigue" 语义。
- **持久化节奏**：record/settle 只改内存字段，搭现有 save 的车（nudge checkpoint / close / 工具批 checkpoint）——**不新增 save**（延续节奏纪律）。
- **L2 与 dsh 先例的关系**：dsh 的 `guard/repeat-tool-reminder`（阈值 [3,5,8]）只做**提醒**；我们按其形态做**阈值检测**，但效果升级为武装期**结构化拒绝**（Q4 已拍）。

### 2.2 D4 `FailedRepeatGuard`（`core/guard.py` 新增；常备、休眠）

```python
class FailedRepeatGuard:
    name = "failed_repeat"
    def __init__(self, threshold: int = 2): ...   # 默认 2
    def reset(self): self._failures = Counter()
    def check(self, call, ctx, view) -> GuardDecision:
        if not getattr(view, "strict_repeats", False): return ALLOW
        fp = call_fingerprint(call)
        if self._failures[fp] >= self.threshold:
            return DENY(f"'{call.name}' failed {n} time(s) with the same arguments; "
                        "read the error and change approach or ask the user")
    def after(self, call, result, ctx, view):
        if not result.success: self._failures[call_fingerprint(call)] += 1
        return result
```

- **常备注入点（核对后的决定）**：`build_guards`（`core/guard.py:46`）当前"无配置返回 None"。改为**以 `FailedRepeatGuard()` 为种子**，永远返回链（docstring 同步改）；「未武装=零行为」由 `view.strict_repeats` 默认 False 保证。`dispatcher` 的 `guards=None → GuardChain([])` 兜底保留（测试直构路径）。
- **计数语义**：`after` 钩子**始终**计数（含未武装期）——武装前的两次失败正是拒绝的依据；`reset()` 每回合随 `guards.reset()`（`_begin_turn` :835 已有）。成功不清零（做减法：清零会让"败-败-成功-败-败-再试"绕过；但已成功过的调用不值得再拒…，因此**该指纹任意成功即从计数删除**——两行代码，避免误伤）。
- **误伤分析**（写进测试）：`bash(pytest X)` 失败 1 次 → 修 → 再跑同命令：计数=1 < 2 → 放行；只有连续 2 次失败后的第 3 次同指纹才拒。
- **价值重述（审核 MEDIUM-2 后）**：默认链已含 `duplicate_call(2)`，第 3 次同参调用**今天已被拒**（探针 P2 原文为证）。L2 的真实增量 = ① 卡死感知的拒绝文案（"read the error and change approach or ask the user"，替代对失败调用具有误导性的 "reuse the earlier result"）② `duplicate_threshold=0` 配置下的覆盖 ③ 账本可见的卡死语义。
- **链序**：`FailedRepeatGuard` 排在 `DuplicateCallGuard` **之前**——武装且目标为失败复现时其文案优先；未武装时零行为，落到既有的通用拒绝。

## 7. 最终模样（实施后自检锚点）

- 会话文件多一个键（任务完成即消失/重置）：`"interventionState": {"strategy": {"level": 2, "at": [3,5], "outcome": "failed"}}`。
- 请求里系统段多一段 `<methods>…</methods>`；tail 第一块是 `工作区:/分支:/日期:`。
- 一个绕圈回合的实录：`[strategy-gate] …` → 模型重复失败调用 → `ToolFinished(success=false, output="'bash' failed 2 time(s)…")`（拒绝）→ `[strategy-gate:L2] …` → `ask_user` → 用户答复 → 继续。
