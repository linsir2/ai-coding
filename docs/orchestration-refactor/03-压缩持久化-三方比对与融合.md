# 编排层深改 · 03 压缩持久化：三方比对与融合

> 背景：本项目最初模仿 GenericAgent 与 OpenCode；现结合 dsh。
> 目的：为"持久化/可恢复"选出压缩的**持久化形态**，融合三方优点，优先保证数据流跑通。
> 来源：`GenericAgent/llmcore.py:52-123`、`opencode/packages/core/src/session/compaction.ts`、`deepseek-harness/packages/{core/session/src/surface.ts,compaction/compaction-basic/src/region.ts}`。

---

## 1. 三方比对（只看与持久化相关的形态）

| 维度 | GenericAgent | OpenCode | dsh | **ai-coding（现状）** |
|---|---|---|---|---|
| 触发 | 每 5 次调用 / cap 超出 | auto / overflow / manual | pressure / context-overflow | 软水位 `should_compact` |
| 手段 | **纯机械**：tag 截断 + FIFO pop | **LLM 摘要**（结构化模板）+ verbatim recent | **LLM 摘要** + tool-result pruner | **4 层**：L3 落盘 / L1 snip / L2 placeholder / L4 摘要 |
| 摘要模板 | 无 | **固定 markdown 模板** + fill 检查 + 一次 nudge | `filled()` 检查 + nudge | 无强模板 |
| **替换形态** | **原地改 list** | **一条 checkpoint 消息替换被覆盖历史** | **`surfaceOp replace{range}`** | **`session.messages = list(result)`（整列表）** |
| 溢出重试 | 无 | `SHRINK_STEPS=[0.7,0.5,0.35]` | shrink 阶梯 | 单次（G5-1） |
| 保留 | `keep_recent` 10/4 | `keep` tokens verbatim | retained tail | `snip_keep_head/tail`、`l4_keep_tail` |
| 崩溃检测 | 无 | 无（有 compaction message 状态） | **`compaction/start`…`/end` 括号**（孤儿锁） | **无** |
| 落盘 | 无（内存） | session log（有事件的） | **surface 事件 + 压缩事件** | 整文件快照 |
| 溯源 | 无 | checkpoint 引用 | **`sourceEventSeqs` 覆盖被遮蔽节点** | 无 |

### 三个"最强项"

- **GenericAgent 最强**：**简单**。机械、无 LLM 调用、零成本。缺点：粗暴 FIFO 丢信息。
- **OpenCode 最强**：**替换语义干净**——摘要被表达成**一条 checkpoint 消息**，替换掉被覆盖的历史。这让"替换"天然可记录、可重放。还带**结构化模板 + 溢出阶梯**。
- **dsh 最强**：**操作被记成日志 + 崩溃可检测**（`compaction/start`…`/end` 括号 = 孤儿锁）+ **溯源**（`sourceEventSeqs` 覆盖每个被遮蔽节点）。

### ai-coding 的独有强项

**4 层压缩**（L3 落盘 / L1 snip / L2 placeholder / L4 摘要）比三家都丰富——GA 只有截断+pop，OpenCode/dsh 只有"摘要 + 保留尾部"。且 L3/L2 把大输出**落盘成文件**（可恢复），是三家都没有的。

## 2. 融合方案：各取所长

**核心判断**：ai-coding 的压缩**策略**（4 层）保留——它最强。要融合的是**持久化形态**：

| 来源 | 融合进来的东西 | 落到哪 |
|---|---|---|
| **dsh** | ① 压缩是一个**有括号的操作**（`compact/start`…`compact/end`）→ 崩溃可检测孤儿压缩；② `compact` 事件**携带被遮蔽消息的 id**（溯源） | `compact/start`、`compact/end`、`compact{shadowedIds, replacement}` 三个事件 |
| **OpenCode** | **替换 = 被覆盖历史被一组新消息取代**（它的 checkpoint 消息模型）→ 重放规则简单：从该点起，历史 = replacement | `compact.replacement` 是**压缩后的完整消息列表**（含摘要 + 存活尾部） |
| **GenericAgent** | **机械 + 无 LLM 的兜底**（它的 pop+truncate 思路已在 ai-coding 的 hard_trim 里）；`sanitize_pairs` 保持 | **不新增**（已有等价物），避免冗余 |
| **ai-coding** | **4 层策略原样保留**；L3/L2 的落盘文件不进日志（它们是**内容**，文件路径在消息里） | 不改 `compress()` 的产出（仍是列表） |

### 为什么不采用 dsh 的 range-granular surface

- ai-coding 的压缩是**整列表变换**（4 层复合 + hard_trim + pinning + sanitize），**不是** dsh 的"选一个范围→一条摘要"。
- 忠实 range-surface 要**把 4 层重写成 emit 范围 ops**——`context_compression.py`（850 行、M3 语义、最多测试保护）大改。
- 这是**邻接范围，不是根因**：北极星是"压缩发生过、结果可重放"，**不需要**范围粒度。
- dsh 自己**对非消息状态也用整值替换**（`task` 事件就是整值）——所以"整值替换"**本身就是 dsh 的模式**。

### 融合后的压缩持久化形态

```
compact/start {compactionId, turn, reason}          ← 括号开（崩溃可检测）
compact {compactionId,
         shadowedIds: [...],                         ← 溯源：被遮蔽的消息 id（dsh）
         replacement: [ChatMessage...],              ← 压缩后完整列表（OpenCode 的 checkpoint 模型）
         summary: {...}, usage?, ...}                ← 摘要元数据
compact/end {compactionId}                           ← 括号闭
```

**重放规则**：apply `message` 事件；遇 `compact` → 派生历史 = `compact.replacement`；其后继续 apply `message`。
**崩溃检测**：有 `compact/start` 无 `compact/end` → 孤儿压缩（合成 `compact/end`，`replacement` 取最后一个**完整**的 `compact`）。
**人类 transcript**：原始 `message` 事件仍在日志里（未被删除）→ transcript 不丢。

## 3. 量化测试（用户要求"量化测试，追求高质量"）

| 指标 | 测法 | 阈值 |
|---|---|---|
| **折叠等价** | `fold(log) == session`（压缩前/后/多次压缩后） | 逐字段等 |
| **重放确定性** | 同一日志两次 fold 字节一致 | 相等 |
| **崩溃恢复** | 在 `compact` 前后各注入一次崩溃，load 后状态正确 | 无数据丢失 |
| **transcript 不丢** | 压缩后，append-origin 消息数不减 | 不减 |
| **孤儿压缩检测** | 只写到 `compact/start` → load 报孤儿 | 检出 |
| **多次压缩** | 连续 5 次压缩后 fold == session | 相等 |

## 4. 与要求 2（显式发射）的衔接

已拍板：**显式发射**（非 diff）。压缩是**显式发射的一等场景**：
- `compact_now` / `compress_if_needed` 成功后，**显式**追加 `compact/start`、`compact`、`compact/end`。
- 不再有 `session.messages = list(result)` 这种"静默替换"——它改成 `session.replace_messages(result)`，该方法**发 `compact` 事件**。
- 于是"整列表替换"这个 diff 无法处理的场景，变成了**显式**事件。**显式发射正好补上 diff 的缺口。**
