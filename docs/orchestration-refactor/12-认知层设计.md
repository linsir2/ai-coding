## 0. 一句话

把"全靠模型一张嘴"的裸循环升级为三层脚手架：**模式**（认知姿态显式化）、**干预系统**（提示词补丁 → 有账本、有效果反馈、有升级阶梯的结构干预）、**认知教育**（静态方法论 + 环境事实）；并补上中断续写与残迹清理。

## 2. 组件一：模式（Modes）

### 2.1 状态与持久化

- `SessionData.mode: str = "normal"`；`to_dict` 非 normal 才写键 `mode`；`from_dict` 读回，**未知值兜底 normal**（fail-safe，不落 plan）。
- 崩溃存活：mode 随会话文件；重启后 plan 模式会话仍是只读姿态。

### 2.2 模式定义表（声明式，一处）

| mode | 提示词段 | 工具闸 | 干预档 | 进入/退出 |
|---|---|---|---|---|
| `normal` | 无 | 全开 | 全表 | 默认 |
| `plan` | 接上现有 `plan_mode` 段（`ai/prompt.py:43-47`，当前死接线） | `mutates_world == True` 的工具一律拒绝（见 2.3） | 关执行类门（task-gate、acceptance），保留 strategy/fatigue/预算 | 显式命令（2.5） |

### 2.3 工具闸（结构性，不只提示词）

- `BaseTool.mutates_world: bool` 新属性，**默认 True（失关闭：未知/新工具在新模式下自动被拒）**；显式 False：`read`/`glob`/`grep`/`todo_write`/`checkpoint_write`/`ask_user`/`skill`。
- 执行点：`ToolContext.mode: str = "normal"`（`_run_tools` 组 ctx 时带 `session.mode`）；`dispatch._decide` 在 unknown 检查之后、gate 之前插入模式闸：拒绝并返回清晰理由（"plan 模式只读：该工具会改变工作区/状态；完成规划后用 /plan off 退出再执行"）——**模型看得见拒绝**（可审计、可学习）。
- 否决备选：换 schema（工具"悄悄消失"）——不采纳（`agent_loop.py:314` 的 schema 是构造期常量；且被禁工具应可见）。

### 2.4 提示词接线

- `PromptAssembler.build(...)` 增参 `mode`（替代构造期 `plan_mode` 布尔——它当前无人传 True）；序：base → project → **methods（组件 A）** → mode 段 → skills。
- `agent_loop._build_instructions`（:1765）传 `session.mode`。

### 2.5 命令面（Q1：`/plan` 重定义为模式）

- `/plan [topic]`：**进入 plan 模式**（`mode="plan"` + save）；带 topic 时同回合发规划提示词（现 `PLAN_PROMPT`）开始"聊商划"；不带 topic 进入后由用户自然语言启动。
- `/plan off`：退出模式（`mode="normal"` + save）；若任务有 open items → 问"发现 N 个计划项，现在执行吗？(y/n)" → 是：**arm + PlanRunner 执行**（即 `plan_and_run` 的执行半边，同一会话立即执行——M1-A 的防变质目的由"同对话交付"承接）；否：保留计划，用户随时可再执行。
- 迁移：`test_plan_command.py` 按新语义重写（sanctioned：Q1 重定义）；`plan_and_run` 拆为"规划轮"与"执行半边"两个可调用入口，执行半边签名不变（`PlanRunner` 零改）。
- UI 最小化：`session.load` 响应带 `mode`；前端 header 显示 plan 标记（小改；若前端工作量超预期，降级为进入/退出时的 notice——实施期定）。

## 3. 组件二：干预系统（`core/interventions.py`，新）

### 3.1 结构

- `Intervention` 冻结数据类：`id / trigger(snapshot) / level（1..L）/ effect kind / text builder / observation window / reset signal`。
- `InterventionSnapshot`：由 books+task+acceptance+session 派生（失败 streak、fatigue、open items、验收态、迭代、tokens、attempted/successful、**intervention_state**）。
- `select(snapshot) -> InterventionDecision | None`（**纯函数**，按优先级取第一个触发且未在观测窗口/未升满者）；`observe(snapshot) -> ledger updates`（窗口结束判 `helped/failed`）；`record(...)`。TurnPolicy 保持纯（预算/时钟/stall 之外的结构决策不变）；loop 调 `select` 并应用效果/记账/save。

### 3.2 干预表（6 门迁入；stall 并入 strategy，sanctioned 重构）

| 干预 | trigger | 效果观测 | 阶梯 |
|---|---|---|---|
| strategy | failed_streak ≥ 2 | 下 2 迭代 streak 复位 = helped | L1 文本 nudge（现文案）→ **L2 dispatch 拒绝"失败调用的重复"**（见 3.3）→ L3 强制 ask_user 指令 → L4 诚实停 + handoff（并入现 stall 语义） |
| fatigue | Paris 指数 ≥ 30 | 损伤增速回落 | L1 nudge → L2 同 strategy → L3 ask_user |
| task-gate | open items 停留（项状态无变化） | 项状态变化 | L1 nudge（≤2）→ L2 ask_user（"还有 N 项，继续还是收尾？"）→ 交用户 |
| acceptance-gate | 验收失败 | 通过率变化 | L1 nudge（附输出尾）→ L2 ask_user → L3 诚实停 |
| continue（C3） | 预算尽且活未完 | 轮后完成度 | 现状（≤3 轮），入表不改行为 |
| budget-pressure | 预算将尽 | — | volatile 预告（现状，入表不改行为） |

- 观测窗口结束后：`failed` → **升级**（level+1）；`helped` → 记账降温。文件位置：`bench` 类信号全部来自现有 `TurnBooks`/`TaskState`/acceptance，**不新增信号源**。

### 3.3 L2 结构性拒绝（Q4，扩展现有重复 guard）

- 现有 R4b 重复调用 guard（`dispatcher.guards`）扩展一个"失败调用复现"级：当 engine 判定 L2 激活（本次或账本中该干预 `level ≥ 2` 且上次 `failed`/`pending`），此后 **N=3 迭代内**，同 `tool+params` 在失败后再次出现 → guard 拒绝，返回"该调用刚失败（重复被拦截）：读错误输出，换手段或 ask_user"。
- 跨回合记忆生效点：新回合 `strategy` trigger 一触发，账本显示上次未 helped → **直接从 L2 开始**（不重走 L1）。
- Guard 状态按回合重置（现状）；L2 激活由 loop 在 dispatch 前写入 guards（engine 决策的一部分）。

### 3.4 账本

- `SessionData.intervention_state: dict | None`（键 `interventionState`，非空才写）：`{round, items: {id: {level, since_round, outcome}}}`。
- 重置边界（Q2）：**任务完成（items 全终态）/ disarm / 新 `/plan`** 时清空；其余跨回合延续。
- 与 11-plan：`disarm` 语义共享；账本文件区独立。

## 4. 组件三：A 认知教育（工具方法论段）

`PromptAssembler` 新 section，草案（实施期成稿，英文与 base 一致）：

```
<methods>
- Read before write: never edit a file you have not read this turn.
- Locate with search; read with line ranges instead of dumping whole files.
- After running a command, check its exit code and output before claiming success.
- Declare parallel-safe tool calls truthfully; independent reads may batch.
- When blocked after two attempts, ask the user instead of repeating the same call.
- Verify the change (run the relevant test/command) before reporting it done.
</methods>
```

## 5. 组件四：B 中断续写（Q3：b2）

- 条件（三条同时满足）：`EngineError` 且 `kind != context_overflow`（含未标注的流中死）；**本步已有 delta 送达**（`books.last_text` 非空或本次增量标记）；非 `length` 截断、非用户取消（Cancelled 路径不经过此分支）。
- 动作：注入合成 user 消息（持久化，同门 nudge 纪律）："上一条回复被中断，从未完成处继续，不要重复已完成的内容。" → `continue`；**有界一次/回合**（books 计数）。
- 对照来源：opencode `llm.ts:35-36` 原文级机制。

3. **L2 guard 误伤**（同参不同意图）：仅"失败后 N 迭代窗口内"生效 + 拒绝文案明确；实施期真机场景验证。
4. **模式闸与 subagent**：subagent 的 ctx.mode 恒 normal（子代理不继承 plan 姿态）——实施期确认并加测试。
5. 与 11-plan 的交叉：`_begin_turn` 区（11 的 save）与 mode 读取互不影响；两计划先后执行时以先到者的行号为准重新定位。
