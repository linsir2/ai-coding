# M1+M2 实施方案（已拍板，2026-10-15）

> 来源：code-review 的 3 个 MEDIUM 中的 2 个（M3 Java 互操作另案）。问卷结论：Q1 注记后 save；Q2 tmp 放父目录。

## 1. 实现内容

- **M1**：`resume_turn` 删 marker 之后、跑回合之前，`[resume]` 注记只在内存——首个 checkpoint 前再崩，待决问题彻底消失（比 resume 前更糟，那时至少还有 marker）。修：注记 `add_message` 后紧跟一次 `self.closer.save(session)`，只在有注记时（情形 A 无新内容，不加）。
- **M2**：`UndoFileStore.save` 逐文件直写，无原子性；崩在 `write_bytes` 中间 → 截断文件，redo 静默恢复坏字节。修：per-file 写 tmp（undo root，`tempfile.NamedTemporaryFile` 保唯一）→ `os.replace` 落位；任一步 OSError 则删 tmp、`continue`（best-effort 不变）。

## 2. 影响与范围

新增函数/契约：**0**。改动：2 产品文件 + 1 测试文件。新增测试 2 个。新增 save 节奏：仅 resume-with-marker 异常路径 +1（常规回合 ±0；全库唯一调 `resume_turn` 的测试不 pin 次数，grep 确认）。
不做：`load()` 读取上限、`_forget_redo` 补 save、`session_id` 校验、`staged_undo` 容错、任何事件/IPC/前端改动。

## 3. 复用（逐个说作用；备选已砍，理由在 08 式记录里）

- `TurnCloser.save`：原子落盘 + 失败降级 + ephemeral 跳过——M1 要的正是这三条。
- `os.replace` + `tempfile`：marker/session 已有两处原子写先例，M2 是第三处同一写法，不引入第三种风格。
- 砍掉：注记块外无条件 save（情形 A 空转）；`name+".tmp"` 手写 tmp 名（与真实 `*.tmp` artifact 相撞）；M2 改 `load` 加 filter（tmp 放父目录后 `load()` 的 `rglob` 只扫会话子目录，残留天然不可见，filter 是多余机制）；抽 helper（多一个契约，内联 8 行）。

## 4. 数据流与效果

- 写路径：resume-with-marker +1 save；sidecar 写变 per-file 原子，调用形状时序全不变。读路径零改。
- 成功后：(1) resume 后再崩，文件里有注记 + `openTurn` + 无 marker → crash-only notice + history 可查；(2) 崩在 sidecar 写中间，盘上是旧完整版或无新版，永不截断，`load()` 看不到 tmp。

## 6. 架构图

```
M1：删marker(durable) ─注记+save(durable)─跑回合─首checkpoint
                          ▲ 崩 → 注记在盘（今天：彻底消失）
M2：mkstemp(undo-root) ─write─os.replace→target；崩 → 旧完整版或无新版
     load() 只扫会话子目录，父目录残留 tmp 天然不可见
```

## 7. 自核验

`self.closer` 同文件三处已用；注记是 user 消息 pairing 恒保留；save 节奏测试无一经过 resume 路径；`os.replace` 同文件系统（同树）；两处 except 都不新增 raise；ephemeral 被 `closer.save` 内 guard 跳过；M1 测试真红过（注记内存态断言败），M2 测试真红过（截断断言败）。
