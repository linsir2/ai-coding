## 3. 设计

### 3.1 模式行与切换
- `Prompt` 增 `mode?: "normal" | "plan"`；metadata 行首渲染模式段：plan → `PLAN`（`theme.feedbackWarning` 加粗），normal → `Build`（muted）；其余 metadata 不变。
- `shift+tab` → `session.mode.cycle`：读 `stats().mode` → 派发内部命令（plan→`/plan off`，normal→`/plan`）；**回合运行中**走既有命令排队路径（前端 `busy` 时按 queued 模式回显），后端 `request_posture` 排队，回合末生效。
- palette：`session.plan` 条目改写为 Toggle（desc "进入/退出计划模式（只读）"），消费同一 cycle。
- 刷新：命令 ack / turn.finished 已有 `refreshStats` 路径（`session.tsx:138,282`）→ chip 自动更新。

### 3.2 `present_plan` 工具与评审卡
- **新文件** `ai_coding/tools/present_plan_tool.py`：`PresentPlanTool(prompt: UserPromptCallback, timeout_seconds=300)`；`parallel_safe=False`、`mutates_world=False`（白名单）。
- 参数：`{"plan": str}`（必填，非空；建议 `#` 开头，不做强校验——省一轮）。
- **校验**：`ctx.task.open_items()` 为空 → 失败结果："计划尚未写成条目：请先用 todo_write 写出可执行项（含 verify），再调用 present_plan。"（error=`no_plan_items`）。
- **阻塞评审**：`await prompt.ask("批准这个计划并开始执行？", ("开始执行", "继续规划"), detail=<markdown>, intent="plan_review")`。
- **答案约定**（评审卡 ↔ 工具私有契约，文档化）：前端 resolve 一个 JSON **字符串** `{"choice":"approve"|"keep","feedback":str?}`；宽容解析：整串 == "开始执行" → approve；其它非空文本 → keep+feedback=原文；`answered=False`（empty/eof/no_user）→ 结果 `{"dismissed":true}`（"用户未答复/搁置；保持计划模式，向用户简要说明计划并停止等待指示"）。
- **工具结果**：approve → `success=True`，output "计划已批准：执行由系统接管（前端将自动开始执行）。请简短收尾，不要开始执行。"，data `{"approved":true}`；keep → `success=True`，output "用户选择继续规划。反馈：{feedback}（若无反馈则：请询问要改什么）。修改后再次 present_plan。"，data `{"approved":false}`。
- 超时/无通道：沿用 ask_user 语义（300s+15 grace；`no_user`→"没有可评审的人，保持计划模式并自行收尾"）。

### 3.3 确认后自动执行
- 评审卡 [开始执行]：`session.tsx` 包装 `onAnswer`——解析 approve → `pendingPlanRun=true` → 照常 `props.onAskAnswer(json)`（工具返回）。
- 本回合（规划轮）继续收尾直至**终态 `turn.finished`**（`session.tsx:280` 处理区）：若 `pendingPlanRun` → 清标志 + `dispatch("/plan run")`（内部命令；此时 busy=false，后端 disarm+PlanRunner 全跑）。
- 统一覆盖两条入口：`/plan <topic>` 命令流 与 模式行下的普通 prompt 流（都是终态 turn.finished）。
- chip 于 run 的 disarm 后回 `Build`；执行体沿用 PlanRunner（步会话、收据、逐步视图零改）。

### 3.4 续跑四件（全部在 `plan_runner.py`，少量 `turn_policy`）
1. **规划轮预算专化**：`continuations_disabled` 换为 `plan_round_policy(loop)`（`replace(config, max_iterations=30, max_auto_continuations=0)`——复用同一 swap 机制，常量 `PLANNING_MAX_ITERATIONS=30`，无新配置）；`PLAN_PROMPT` 增："先写下全部骨架项（每项一句话+verify），再按需细化；了解代码用 grep/glob 定位关键段，避免为写计划通读大文件。"
2. **步猝死续跑**：`_run_step` 内、`_settle` 前——若步回合终态 reason == "iteration budget exhausted" 且项未完成且续跑次数 <1 → 再跑一次，prompt=`STEP_HEAD + "上一步预算用尽但本步未完成：从停下的地方继续，只做这一步。"`（不复用 C3 的通用 continue 文案，避免引到其它计划项——保持 `max_auto_continuations=0` 不变）；续跑计入 `turns_used`。
3. **stall 不杀整跑**：`if report.stalled: break` 改为记录后 `continue`（`attempted` 集防死循环；stalled 项保持 open；末尾报告照旧列"停滞（下次可重跑）"）。blocked 维持现状（本项 blocked 即停）——最小改动面。
4. **重试带进度**：`_seed` 增一段——若 `session.step_deliveries` 中有本项（同 statement）的历史收据（stalled/blocked），追加："该步此前已尝试 N 次；上次结果：{最后一条 summary}。从上次停下的地方继续，不要从头再来。"

### 3.5 语义修正
- **完成门**：`todo_write` update→completed 且 `ctx.readonly` → 失败结果（error=`readonly_completion`，"完成标记由执行阶段产生：只读/规划期请保持 pending；执行请用 /plan run 或结束规划模式。"）；add/clear/其它状态不受影响。
- **"计划就绪"文案**：仅 `present_plan` 成功路径出现（后端工具结果+前端卡片即为信号）；`_handle_plan` 里旧的 items 计数成功提示**删除**（规划轮结束≠计划就绪）；预算猝死时提示改为"[plan] 规划未完成（预算耗尽）：可继续对话补充，或重新描述需求。"
- **上下文表口径**：页脚 `context_tokens` 现显示本回合累计 prompt tokens（复现：279,045 (581%) 与本回合 turnUsages 相等；压缩后不回零）。修正为**当前上下文估算**（与压缩联动），若实现期证实成本高，退而求其次：标签改"本回合 tokens 累计"（文案级）。

## 4. 数据流（改后）

```
[模式行] shift+tab / palette
   └─ dispatch 内部命令 "/plan" | "/plan off"  ← 回合中：request_posture 排队，回合末生效+落盘
[规划轮] /plan <topic> 或 模式行下的普通 prompt
   ├─ 只读闸：write/bash 拒；todo_write 放行；update→completed 拒（Q6 门）
   ├─ 预算 30：骨架项优先（PROMPT 引导）
   └─ 模型调 present_plan(markdown)
        └─ 阻塞于 prompt.ask(intent="plan_review", detail=markdown)
             └─ 前端 PlanReviewPanel（prompt 槽位）
                  ├─ [开始执行] → resolve {"choice":"approve"} → 工具返回 approved
                  │     └─ 本回合收尾 → 终态 turn.finished → 前端 dispatch("/plan run")
                  │           → 双关落盘 → PlanRunner 逐步执行（猝死续跑/stall 跳过/进度注入）
                  └─ [继续规划+反馈] → resolve {"choice":"keep","feedback"} → tool-result 回填
                        → 同轮修订 → 可再次 present_plan；[esc]=dismissed 语义
```
