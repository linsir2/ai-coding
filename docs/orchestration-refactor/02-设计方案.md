# 编排层深改 · 02 设计方案

> 目标（北极星）：**持久化与可恢复**。四个场景全要：崩溃续跑 / 跨会话 resume / 审批挂起 / undo-redo 持久化。
> 已拍板：① 放弃 Java 兼容 ② 独立 `.jsonl` 日志（`session.json` 降为派生快照）③ 消息加稳定 id ④ 本轮只做持久化层（不碰三域事件、不加水fall）。
> 原则：最小化、第一性原理、只改根源、只做相关；说不清作用的契约/函数一律砍。

---

## 0. 一句话方案

**把"会话"从「可变快照（整文件重写）」改成「append-only 事件日志（`<id>.jsonl`）」，`SessionData` 变成日志的折叠产物。** 四个恢复场景都是同一根因的症状——**历史不落盘**——所以都从这个改动里自然获得。

---

## 1. 现状与根因

| 层 | 现状 | 根因 |
|---|---|---|
| 会话 | `SessionData` 可变 dataclass，`messages` 是状态 | **"现在是什么"落盘，"发生过什么"不落盘** |
| 持久化 | 整文件 JSON 重写（tmp+rename） | 无历史、无增量、无崩溃检测 |
| 回合 | checkpoint 存消息列表，**无 turn 边界标记** | 崩溃后不知道有 turn 在飞 |
| 审批 | 内存 await，server-initiated request | 不是 durable 事实，进程死即丢 |
| undo/redo | 历史半边在内存（`_undo_tail`/`_undo_state`/`_undo_files`） | 重启丢 redo |
| 消息 | 靠位置关联 | 无法跨表示追踪 |

**根因一句话**：持久化是**快照语义**，而四场景要的是**日志语义**。

---

## 2. 复用的契约（不新造，只扩展）

| 契约 | 位置 | 复用方式 |
|---|---|---|
| `ChatMessage` | `domain/message.py` | **加一个 `id` 字段**（其余不动）；`to_dict`/`from_dict` 扩展 |
| `SessionData` | `domain/session.py` | **保留为折叠产物**（读取用），不再是写入口 |
| `TurnOutcome` / `TurnStatus` | `domain/loop.py` | `turn/end` 事件直接存它们，**不改** |
| `TaskState` / `TurnDigest` / `AcceptanceItem` / `StepDelivery` / `TurnUsage` | `domain/*.py` | 各自的 `to_dict`/`from_dict` 直接做事件 payload，**不改** |
| `SessionService` | `service/session_service.py` | **原地重构**为日志存储（`create/save/load/list/delete` 签名对调用方不变） |
| `SnapshotStore` / `RestoreReport` | `core/snapshots.py` | undo/redo 的**文件半边不动**；只把**历史半边**落成事件 |
| `ApprovalResult` / `ApprovalCallback` | `security/approval.py` | `approval/decided` 事件存 `ApprovalResult`，**不改** |
| `TurnCloser` | `core/turn_close.py` | `save()` 从"整文件写"改成"追加事件"；**checkpoint/finalize 语义不变** |

**不新增任何重复的领域类型。** 事件 payload 就是既有 `to_dict`。

---

## 3. 数据流：改前 vs 改后

**改前**
```
AgentLoop 写 SessionData(messages/task/…)
  → TurnCloser.save() → SessionService.save() → to_dict() 整文件 → os.replace
读：SessionService.load() → from_dict() → SessionData
```

**改后**
```
AgentLoop 写 SessionData (内存模型不变)
  → TurnCloser.save()/checkpoint() → SessionService.append(events)  ← 只追加"变了的事件"
  → 派生快照：session.json（可选，缓存；由日志重建）
读：SessionService.load() → 逐行折叠事件 → SessionData
崩溃后：日志里 open turn/start 无 turn/end → 合成 closer + 标记 interrupted
```

**关键**：`AgentLoop` 的**业务代码几乎不动**——它照旧写 `SessionData`。改动集中在**持久化层**：`TurnCloser` 把"写会话"的动作改成"diff 出事件并追加"。

## 4. 事件词汇（最小集，每个都附"为什么存在"）

文件：`<sessions_root>/<session_id>.jsonl`，一行一事件。

```json
{"seq": 0, "time": "2026-10-15T...Z", "type": "turn/start", "data": {"turn": 1}}
```

| type | data | 为什么存在（不存在的替代） |
|---|---|---|
| `session/created` | `{sessionId, title, createdTime}` | 头信息。**替代**：单独 metadata 文件（多余，头就是第一行） |
| `turn/start` | `{turn}` | **崩溃检测的唯一依据**。**替代**：无（这正是缺的东西） |
| `turn/end` | `{turn, status, reason, usage?, handoff?, closing?}` | 关回合 + 携带 token 账目。**替代**：单独 `usage` 事件（冗余，一个回合一个，合进 end） |
| `message` | `ChatMessage.to_dict()`（含新 `id`） | 消息历史。**替代**：无（消息本就是主体内容） |
| `task` | `TaskState.to_dict() \| null` | 任务态整值替换。**替代**：无（lista 语义就是整值替换） |
| `digest` | `TurnDigest.to_dict()` | 回合摘要环。**替代**：从 `turn/end` 派生（摘要内容杂，不派生，直接存） |
| `acceptance` | `[AcceptanceItem.to_dict()]` | 验收契约整值替换。 |
| `delivery` | `StepDelivery.to_dict()` | plan 步收据。 |
| `compact/start` | `{compactionId, turn, reason}` | **压缩括号开**：崩溃可检测孤儿压缩（dsh 的锁）。**替代**：无（这正是缺的崩溃检测） |
| `compact` | `{compactionId, shadowedIds:[...], replacement:[ChatMessage...], summary?, usage?}` | **压缩结果**：被遮蔽的消息 id（dsh 溯源）+ 压缩后完整列表（OpenCode 的 checkpoint 模型）。**替代**：dsh 的 range-granular surfaceOps（见 03 篇：ai-coding 压缩是整列表变换，忠实 surface 要重写 850 行压缩，属邻接范围非根因） |
| `compact/end` | `{compactionId}` | **括号闭**；有 start 无 end = 孤儿压缩 |
| `harvest` | `{count}` | 记忆收割游标。 |
| `approval/asked` | `{requestId, toolName, params, reason}` | **审批 durable 化**（场景③）。 |
| `approval/decided` | `{requestId, outcome}` | 审批结论。 |
| `undo` | `{removedMessages:[...], turnCount, digests}` | **undo durable 化**（场景④）：携带被移除的消息，redo 才有得恢复。 |
| `redo` | `{restoredMessages:[...], turnCount, digests}` | redo 的逆操作。 |

**折叠规则**：按 seq 顺序应用；`turn_count` = 最大 `turn`；`last_access_time` = **最后一行事件的 `time`**（不新增 `touch` 事件——那会污染日志）；`messages` = `message` 事件追加，遇 `compact` 整值替换，遇 `undo`/`redo` 替换。

**派生字段**（不落盘、由折叠算出）：`turn_usages`（取各 `turn/end.usage`）、`last_compacted_turn`（最后一个 `compact.turn`）、`message_count`（messages 长度）、`first_preview`（首条 user message）。

## 5. 崩溃修复（场景①）

**检测**：折叠时若存在 `turn/start` 而其后无 `turn/end`（按 seq），则该回合 open。

**修复**（`SessionService.load` 内，或独立的 `session_log.repair`）：
- 为 open 回合**合成**一条 `turn/end {turn, status: "interrupted", reason: "crash-recovered"}`（新增 `TurnStatus.INTERRUPTED`）。
- 已落盘的事件**保持原样**（不重写历史）。
- 返回的 `SessionData` 带一个 `interrupted_turn: int | None`（**内存态**，供上层决定是否提示"上次回合未完成"并续跑）。

**续跑的语义**：续跑 = 用当前（已 checkpoint 的）消息**重跑模型步**。因为 checkpoint 发生在工具批次之后，重跑一步是安全的（工具结果已落盘，配对完整）。

**新增 `TurnStatus.INTERRUPTED` 的理由**：现有 7 个终态没有"崩溃后补记"这一种；不新增就无法在历史里诚实标注。

## 6. 审批 durable（场景③）

**现状**：`_install_providers` 里 `approval_provider` 发 `approval.request` 并 await。

**改造**：
1. `ToolDispatcher` 在调用审批回调**之前**追加 `approval/asked` 事件；拿到答案后追加 `approval/decided`。
2. `approval/asked` 落盘后，**即使进程退出，重启 `load` 也能看到"有一个待决审批"**。
3. **挂起/恢复**：本轮先做**"重启后发现待决审批"**（`SessionData.pending_approval: dict | None`，内存态）——即"审批挂起"的最小可用形态；**真正的跨重启续跑审批**（用 requestId 重发审批请求给前端）留到验收里明示为后续项。

> **取舍**：不做"进程退出后前端仍能应答"（那需要前端也持久化 pending）。本轮做到"审批入日志、重启可查、可重发"。

---

## 7. undo/redo durable（场景④）

**现状**：`_undo_tail`/`_undo_state`/`_undo_files` 是 `dict[session_id, ...]`，重启丢。

**改造**：`undo_last_turn`/`redo_last_turn` 在末尾各追加一条 `undo`/`redo` 事件，携带：
- `undo`: 被移除的消息列表、staged 的 `turn_count`/`digests`。
- `redo`: 恢复的消息列表、`turn_count`/`digests`。

**文件半边不动**（`SnapshotStore` 的 git refs 已持久化）。
**内存态删除**：`_undo_tail`/`_undo_state`/`_undo_files` 从"权威"降为"缓存"（或直接删，改从日志折叠）——**砍冗余**。

> TDD：每步先写红测试，再实现，再验证，再重构。

### 新增

| 文件 | 内容 | 为什么需要（不做的后果） |
|---|---|---|
| `domain/session_events.py`（纯，无 I/O） | 事件词汇：`SessionEvent` 冻结 dataclass 族 + `to_dict`/`from_dict` + `fold(events) -> SessionData` + `diff(old, new) -> [events]` + `repair(events) -> [events]` + `is_turn_open(events)` | **核心**。事件定义、折叠、diff、崩溃修复的唯一位置 |

> **两处自我删减**（第一性原理 + 现有分层）：
> ① 不新增 `core/session_log.py`——**append/iterate 是 I/O，属 `service/`**，直接原地重构 `SessionService`；**事件词汇/折叠/修复是纯契约，属 `domain/`**。拆成两个文件是冗余。
> ② **不新增持久化"接缝"三角**（definition/provider/consumer）：只有一个 provider（JSONL），dsh 自己的 AGENTS.md 规定"不预先拆分一个只有一个 provider 的能力"。形式化接缝是造轮子。

### 修改

| 文件 | 改动 | 步骤 |
|---|---|---|
| `domain/message.py` | `ChatMessage.id: str`（创建时铸 uuid）；`to_dict`/`from_dict` 带 `id`；老文件无 id 时**回填**（加载时铸） | 加字段 → 序列化 → 兼容回填 |
| `domain/session.py` | 保留 `SessionData` 作为**折叠产物**；`from_events(events)` 类方法；`to_dict` 保留（供快照缓存）；新增内存态 `interrupted_turn`、`pending_approval` | 加 `from_events` → 加内存态字段 → 标注哪些是派生 |
| `domain/loop.py` | `TurnStatus` 加 `INTERRUPTED` | 一行 |
| `service/session_service.py` | `create` 写 `session/created`；`save`→`append(diff)`；`load`→`fold` + `repair`；`list_sessions` 读首行(头)+末行(last_access) | create → append → fold → list |
| `core/turn_close.py` | `save()` 改为 `SessionService.append(events)`；`checkpoint()` 同理；**diff 出的事件**由 `session_events.diff` 从上次持久化状态与当前状态算出 | save → checkpoint |
| `core/agent_loop.py` | `undo_last_turn`/`redo_last_turn` 追加 `undo`/`redo` 事件；**删除** `_undo_tail`/`_undo_state`/`_undo_files` 三个内存字典，改从日志折叠 | undo → redo → 删字典 |
| `security/approval.py` | 审批回调**不改**；`ToolDispatcher` 在调用前后追加 `approval/asked`/`decided` | — |
| `core/dispatch.py` | 调用 `@` 前后追加审批事件（拿 `emit` 或注入 `SessionService`） | — |
| `server/handlers.py` | `session.prompt` 的 load 若发现 `interrupted_turn`，提示并可续跑；发现 `pending_approval`，重发审批 | — |

**"显式发射"的机制**（已拍板，替代影子 diff）：
`SessionData` 的**所有变更走明确的方法**，每个方法发事件；`TurnCloser`/`SessionService` 只负责把待发事件追加到日志。
- `append_message(msg)` → `message`；`replace_messages(new_list, shadowed_ids)` → `compact`；`set_task(t)` → `task`；`bump_turn()`；`append_digest(d)`；`record_usage(...)`；`set_compaction_turn(t)`；`set_acceptance(items)`；`append_delivery(d)`；`set_harvested(n)`；`append_undo(...)`/`append_redo(...)`。
- **~15 处直接字段写入**（`session.messages = …` / `session.task = …` / `session.turn_count += 1` …）改为对应方法调用。
- **否决影子 diff**：压缩/undo 的整列表替换 diff 无法推断范围（会误判成"删一堆+加一堆"），pinning 追加还会乱序（见 03 篇 §1）。
- **否决自动发射 setter**：`session.messages.append(m)` 是原地变更，setter 不触发，不可靠。

> **诚实修正**：这**不是**"业务代码零改"。~15 处 writer 代码要改成方法调用。但改动是机械的，且换来稳健（不依赖 diff 推断）。

## 9. 架构图

```
┌──────────────────────────────────────────────────────────────┐
│ AgentLoop.process_input  (业务代码，几乎不改)                  │
│   写 SessionData(messages/task/…)                              │
└───────────────┬──────────────────────────────────────────────┘
                │ save()/checkpoint()
┌───────────────▼──────────────────────────────────────────────┐
│ TurnCloser                                                     │
│   diff(_persisted, session) → [SessionEvent]   ← session_events│
│   SessionService.append(events)                                │
│   _persisted = session                                         │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│ SessionService  (原地重构)                                     │
│   append: 原子追加一行到 <id>.jsonl                            │
│   load:   逐行 fold → SessionData；repair 补 open turn         │
│   list:   读首行/末行                                          │
└───────────────┬──────────────────────────────────────────────┘
                │
        <sessions_root>/<id>.jsonl   ← 唯一真相源
        <sessions_root>/<id>.json    ← 派生快照（缓存，可由日志重建）

崩溃后: turn/start(open) → repair 合成 turn/end{interrupted}
审批:   approval/asked → approval/decided
undo:   undo{removed…} → redo{restored…}
```

## 10. 成功后的效果（最终模样）

1. **崩溃续跑**：kill -9 后重启，`load` 报"上次回合未完成（turn N）"，可一键续跑（重跑模型步）。
2. **跨会话 resume**：`/resume` 从日志折叠出会话；消息带稳定 id，可跨快照/日志/内存关联同一消息。
3. **审批挂起**：审批请求落日志；重启可见 `pending_approval` 并重发。
4. **undo/redo 持久化**：重启后 `/redo` 仍可用（历史从 `undo` 事件折叠）。
5. **对账不变量**：任意时刻 `fold(log) == session`（快照只是它的缓存）。
6. **业务代码零改动**：`AgentLoop` 的迭代/工具/压缩逻辑一行不改。

## 13. 分期（每期可独立验收、可回退）

| 期 | 内容 | 验收 |
|---|---|---|
| **P1 双写** | 加事件词汇 + `TurnCloser` diff/append；**读写仍走快照**，日志只写 | `fold(log) == 快照` 对账通过；全部现有测试绿 |

| **P3 恢复三件套** | 崩溃修复 + 审批 durable + undo/redo durable | 四个场景各有端到端测试 |
