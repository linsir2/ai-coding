# 编排层深改 · 06 补充式实施方案（定稿）

> 本方案**取代 `04-完整实施方案.md`**（那份是 append-only 全量改造，已证伪为过度工程）。
> 原则：**基于现有分层补充，能融合就融合，不好才改造**。北极星：持久化与可恢复（④场景）。
> 已确认：Q1 保留消息 id；Q2 ②resume 现状已够（不加请求头）；Q3 undo 文件字节走 sidecar。

## 0. 目标与根因（修正版）

**原层没坏**——它是原子写、checkpoint、失败降级的合格快照，resume 已可用，历史另有轨迹。
**真缺口只有 3 条**：

| # | 缺口 | 场景 |
|---|---|---|
| G1 | 无"回合开着"标记 | ① 崩溃续跑 |
| G2 | **审批 await 在 save 之前**（唯一真 bug） | ③ 审批挂起 |
| G3 | undo/redo 历史半边在内存 | ④ undo/redo |

**根因一句话**：**3 个事实没有被写进会话文件**（回合开着 / 待决审批 / undo 状态）。**修根源 = 把这 3 个事实落盘**，不是换存储模型。

## 5. 新增功能：每文件每步

### 5.1 `domain/message.py`
- **步 1**：`ChatMessage` 加 `id: str = ""`。
- **步 2**：`__post_init__` 末：`if not self.id: object.__setattr__(self, "id", uuid4().hex)`。
  - **为什么**：15 构造点零改；`from_dict` 传已存 id 则保留。

### 5.2 `domain/session.py`
- **步 1**：加 3 持久化字段：
  - `open_turn: int | None = None`（键 `openTurn`）
  - `pending_approval: dict | None = None`（**仅运行时**，由 marker 文件填充，**不进会话 JSON**）
  - `undo_state: dict | None = None`（键 `undoState`：`{removed:[msg], turnCount, digests}`）
- **步 2**：加 1 内存字段 `recovered_interrupted: bool = False`（**不落盘**，白名单不含）。
- **步 3**：`to_dict` 仅非 None 写这 3 键（沿用现有"仅非空才写"纪律）；`from_dict` 读回。
- **步 4**：`_message_to_dict` 写 `id`（非空才写）；`_message_from_dict` 读 `id`（缺失→`""`→`__post_init__` 回填）。

### 5.3 `core/agent_loop.py`
- **G1**：
  - `_begin_turn`（705）：只设 `session.open_turn = turn_number`（**不新增 save**）。
    - **实施期修正**：原方案写"随后 save 一次"。实现时发现那会改变**保存节奏**，撞坏 3 个既有测试（含一条 golden recording 的 `saves` 计数）。**测试没错，是设计多余**——marker 设为内存后，**搭下一次现有 save（首个 checkpoint 或 close）的车**即可：崩溃发生在首个 checkpoint 之前时本就没有产出可丢（与改动前同窗口），发生在之后时 marker 已在盘上。
  - `_close_turn`（940）：`session.open_turn = None`，随 `closer.close()` 的既有 save 落盘（**所有退出路径的唯一漏斗**）。
- **G2（接线）**：构建 `ToolContext` 时注入 `note_approval=lambda p: self._note_approval(session, p)`：
  - `_note_approval(session, pending)`：`session.pending_approval = pending`；`self.closer.save(session)`。
- **G3**：
  - `undo_last_turn`（1398）：把 `_undo_tail`/`_undo_state` 的**消息半边**写进 `session.undo_state`，保存；**文件字节**写入 sidecar（见 5.5）。
  - `redo_last_turn`（1507）：清 `session.undo_state`，删 sidecar，保存。
  - 新增 `_hydrate_undo(session)`：`redo` 开头若进程内字典为空，从 `session.undo_state` 重建（消息 + turns/turnCount/digests）。
  - **`_forget_redo` 必须一并清** `session.undo_state` + sidecar：新回合提交暂存回退，不清就会让后来的 `/redo` 复活用户已经翻篇的那一轮（实测撞坏 2 个 r17 集成测试）。

### 5.4 `core/dispatch.py` + `tools/base.py` + `service/session_service.py`
- `ToolContext` 加 `note_approval: Callable[[dict|None], None] | None = None`（对标 `note_checkpoint`）。
- `dispatch._decide`（352）：在 `self.approval.approve(...)`（438）**之前**调 `ctx.note_approval({callId, toolName, params, reason})`，**之后**调 `ctx.note_approval(None)`。
  - **为什么**：这是**唯一真 bug 的修复**——审批前落盘，崩溃不丢。
- **实施期重大修正**：原方案说"写进会话字段，审批前 `save(session)`"。实现时发现**会毁数据**（实测）：
    `ensure_tool_pairing` 在半批状态（call 已发起、result 未写回）**会丢弃 assistant 载具**，而 `TurnCloser.save` 每次都调它。
    所以**批中 save = 丢掉待决调用**，且会打乱保存节奏（撞坏 6 个测试，含 golden recording）。
  - **改为 marker 文件**：`SessionService.mark_pending_approval(session_id, request|None)` 写/删 `<id>.pending.json`，**零 session save**。
    `load` 时读进 `pending_approval` 字段。与 Q3 的 undo sidecar 同一思路：**大/脆的状态进快照，小而独立的事实进 sidecar**。
  - **未覆盖窗口（诚实）**：首个 checkpoint 之前（会话文件尚不存在）崩溃时，marker 无主，行为与改动前一致（本来就无可恢复内容）。

### 5.5 `core/undo_store.py`（新，小）
- `UndoFileStore`：`save(session_id, files) -> None`（合并写）/ `load(session_id) -> dict[str,bytes]` / `clear(session_id)`；路径 `<workspace>/.ai-coding/undo/<session_id>/<rel>`。
- **实施期补充**：`_resolve` 拒绝 `..`/绝对路径（这些路径来自工具 artifact，否则成了越界写口）；`save` 是 best-effort（undo 已经发生，留不下副本不能变成用户可见错误）。
- **为什么**：`_undo_files` 的字节（MB 级）不能塞会话 JSON；sidecar 目录避免膨胀。
- **砍**：不新造抽象基类/接缝（单实现）。

### 5.6 `server/handlers.py`
- `session_load`/`session_prompt`：load 后若 `session.open_turn` 非空 → 发一条 notice（`recovered_interrupted`）；若 `session.pending_approval` 非空 → 重发 `approval.request`。

## 6. 数据流影响

```
写: 回合开始 → session.open_turn=N → save(+1次)
    审批前 → session.pending_approval={...} → save(+1次，审批是低频)
    undo/redo → session.undo_state → save(已有) + sidecar 字节
读: load → SessionData(含3字段) → 若 open_turn 非空 → recovered_interrupted
                                → 若 pending_approval 非空 → 重发
                                → _hydrate_undo(从 undo_state + sidecar)
```
- **写路径**：多 2 次 save（回合开始 / 审批前），其余搭现有 save。
- **读路径**：load 多读 3 个键 + 一次 sidecar 读。
- **内存模型**：`SessionData` 不变；三个 undo 字典降为缓存（load 时 hydrate）。

---

## 7. 修改成功后的效果

1. **崩溃续跑**：kill -9 后重启，`load` 见 `open_turn` 非空 → 提示"上次回合未完成"。
2. **resume**：现状不变（已可用）。
3. **审批挂起**：崩在审批 await 上 → 重启 `pending_approval` 仍在 → 重发审批。
4. **undo/redo 持久化**：重启后 `/redo` 仍可用（`undo_state` + sidecar）。
5. **消息稳定 id**：全消息有 id。
6. **其余一切不变**：读路径、压缩、事件、快照格式、Java 兼容。
