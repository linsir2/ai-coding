## 2. 三把尺子

### 2.1 体积：`referenced_files` 是唯一的失控项

- S3 每次请求 **40,138 字符**的 `referenced_files`，是配置预算（6000 tok）的 **2.5 倍**；
  体积占比 **96%**（40,138 / 41,777），其余所有内容加起来不到 4%。
- 同一文件在 11 次迭代里**一字不变地重发 11 次**；压缩三层都碰不到它（它是 tail 块，压缩之后才拼上）。
  于是出现"压缩越压越勤、请求始终超预算"：est 15,739 → 20,267，是 6k 预算的 **2.6–3.4 倍**。
- 反过来，正常任务（S1）tail 只有 255–694 字符，占 6k 预算的 4–11%，健康。

### 2.2 命中：一半的块"出现在请求里"但没进模型的动作

S3 的答案链条是 `read 6 块 → grep 1 次 → 再 read 同样 6 块（重复） → 被强制收尾`。
逐块看命中：

| 块 | 独有信息 | 是否被用上 |
| --- | --- | --- |
| `referenced_files` | 文件前 497 行 | **用了，而且误导**：模型 i2 说"内容已经在 referenced-files 里，前 ~3000 行可见"，实际只有 497 行 |
| `read_ledger` | `1-3000（缺 3001-6000）` | **没用上**：紧接着它又读了 0–2500（已读过的区间）|
| `task` | 目标原句 | 用上了（摘要里保留了目标）|
| `anchor` | 与 `task` 同一句话 | 与 `task`、摘要 `## 目标` **三处重复** |
| `environment` | 工作区/分支/时间/压缩提醒 | 工作区用了；时间行每迭代都变（见 2.3）|

### 2.3 缓存：尾部一抖，前缀全废

- S1：ratio 0.94–0.97，缓存友好；S3：ratio **0.28–0.35**，因为每次迭代 `environment` 的
  `时间: 2026-10-29T11:14:25+08:00` 都不同，而它在 tail 的第 1 块 —— 后面 40k 的引用正文全部失去前缀复用。
  `environment` 从 107 涨到 158 字符也只因为多了一行压缩提醒。
- 结论：**时间戳放在体积最大的块之前**，把整段尾部排除在缓存之外。

## 4. 两层"给模型的记忆"是否有效

### 4.1 L4 摘要（压缩层）

结构是好的——`目标 / 约束与要求 / 决策 / 工作状态（已完成·进行中·阻塞·已尝试且失败）/ 下一步 / 关键文件 / 重要上下文`，
还带"决策已被新策略取代"这种演化痕迹。模型也确实照它行动（下一步写"对 grep 结果计数"，模型就去做）。

**但它写错了一个事实**：

```
### 已完成
执行 grep({"pattern": "ERROR", ..., "limit": 1000}) 成功获取全量 ERROR 匹配结果。
工具输出已覆盖至文件末尾附近（最新匹配行为第 5994 行），确认遍历完整。
```

grep 结果只是 1000 条上限内的一批匹配，摘要却写成"确认遍历完整"。模型据此不再计数，
最终只报了前 497 行里的 12 条（真值 162 条）。**这是本轮唯一一次"上下文把模型带偏"的实证**，
比任何体积问题都严重：不是给多了，而是给错了。

候选：摘要 prompt 里加一条硬约束——"只有工具结果里出现 `exit_code=0` 且证据覆盖全量，才能写'已完成/确认完整'；
否则写'部分完成 + 缺什么'"。

### 4.2 read_ledger（证据层）

`本会话已读（行号；内容不在上下文里，需要时按缺口重读）：data/big.txt 共 6000 行：1-3000（缺 3001-6000）`
—— 这句本身完全正确，且正是模型需要的。问题是它排在 `referenced_files`（40k）之后，
模型先被正文淹没，再看到 121 字符的账本，等于把地图放在 40 页正文后面。**位置比内容更致命**。

### 4.3 任务锚点三重复

同一句目标在同一个请求里出现 3 次：`task-state`（235 字符）、`task-anchor`（232 字符）、摘要 `## 目标`。
三者都是"别跑偏"，但没有任何一条给出"现在第几步/还差什么"。

## 7. 结论

- **信息给够了，但没有给对位置、也没有给对真假**：`read_ledger` 是对的，却排在 40k 正文之后；
  摘要是结构化的，却把"部分证据"写成"已遍历完整"，直接把模型带偏（12/162）。
- 真正挡住"有效思考"的不是 12 块的设计，而是 **`referenced_files` 这个例外**：它绕过了压缩、
  按"前 N 字符"截断、每次重发，在 6k 预算下让整个压缩机制空转。
- 缓存指标给出一个反直觉结论：**S1（小 tail）ratio 0.96，S3（大 tail）0.30** —— tail 越大，越该小心摆放，
  而 `environment` 的时间行恰好摆在最前面。
