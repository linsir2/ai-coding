# dsh 学习笔记 00 · 定位与全景

> 对象：`deepseek-ai/deepseek-harness`（简称 **dsh**），DeepSeek AI 开源的 agent harness，MIT。
> 快照：`master` @ `5719020`（0.2.1-alpha.3 附近），浅克隆于 2026-10-14。
> 规模：58 个 package、5101 个 `.ts`、60 篇子系统文档（全双语）、**2526 篇决策记录**。
> 本系列目标：不是复述文档，是提炼「它为什么这么设计」和「哪些能搬回 ai-coding」。

## 1. 一句话定位

dsh 不是"一个 agent"，是**一整套可组合的 agent 运行时**。它把产品拆成 58 个插件包，靠配置在启动时拼成一棵树；**没有任何特权内核**——你要扩展，只能"在旁边挂一个插件"。

官方自述（`README.zh.md`）："构建于**一切皆插件**的架构之上，由 **Cordis** 驱动。"其设计论文是《A Programming Paradigm for Spatiotemporal Composability》(arXiv 2608.25512)。

---

## 2. 核心哲学：一切皆插件

`docs/architecture.md` 开篇即定调：

> Every part of the product is a plugin, including the model adapter, the tool registry, the session log, and **the agent loop itself**, so each is replaceable from configuration.
> There is no privileged core to patch.

**连 agent loop 本身都是插件**（`core/agent-loop`），它实现 `core/agent` 定义的 `Agent` 接口——该接口**零 loop 依赖**（`packages/core/agent/README.md`），所以循环可换。

底层是 **Cordis**：一个插件框架，插件向共享 `ctx` 贡献**服务、类型化事件、可逆副作用**。关键约束（`AGENTS.md`）：

> **Registrations are effects**: every contribution goes through `ctx.effect()` / `ctx.on()`; a registry's `register()` returns the disposer.

即：注册即副作用，插件卸载时自动回收。这是"可组合"的机制基础。

---

## 3. 组合机制：profile / bundle / patch

一次运行中的 `dsh` 是**启动时按有序层组合出来的插件树**。

| 概念 | 定义 | 声明位置 |
|---|---|---|
| **profile** | 命名的组合，存在 Harness home；列出它叠加的 bundle、装哪些树外插件、用户的 `cordis.patch.yml` | `package.json` 的 `dsh.profile` |
| **bundle** | Cordis 配置行 + 其挂载代码的分发格式；插入的东西**仍可被上层 patch** | `package.json` 的 `dsh.bundle` 指向 patch 文件 |
| **patch** | 按 id 定位一行、整体替换其 config，或插入新行 | `cordis.patch.yml` / `--patch` |

内置 profile：`web`、`headless`、`sdk`、`sdk-minimal`、`acp`。共享第一层是 **`dsh-base`**（模型适配器、工具、持久化、沙箱与审批策略、settings、credentials、telemetry）；其上叠加 `dsh-web-app` / `dsh-headless` / `dsh-sdk-app` / `dsh-acp-app`。

**层应用顺序**（`docs/architecture.md:25`）：profile 的有序 bundle → 它的 `cordis.patch.yml` → home patch → `--patch` overlay。

查看本机启动的树：`dsh --profile web --dump-config`——**它打印的每一行都能被你自己的 patch 替换**。

## 5. 三类事件（扩展点的第一决策）

`docs/architecture.md:69`——"选对事件域是多数改动的第一个决定"：

| 域 | 是什么 | 用途 |
|---|---|---|
| **Session 事件** | 落盘、广播（`session/event`）的**durable fact** | 需要跨 reload 存活的事实 |
| **Agent 事件**（`agent/*`） | 携带活体 `Agent`：inbox、step、status、request、validation、continuation | 观察/拦截**在途**工作 |
| **Capability 事件** | 给接缝挂策略与适配器（`fs/*`、`tools/*`、`telemetry/*`），**不 import loop** | 加策略而不碰循环 |

Waterfall 语义（`AGENTS.md:136`）：**waterfall listener 必须调 `next()` 才能委派**，不调就短路整条链。`agent/pre-step`、`agent/request`、`llm/stream`、三个 `tools/*` 是 waterfall；`agent/turn-stopping` 是 serial，没有 `next()`。

## 6. Turn flow（一次回合的骨架）

`docs/architecture.md:83` 给出骨架。**step = 一次模型请求 + 它触发的工具**；**turn = 零或多个 step**：在第一次 input 被 claim 前打开，在"没有任何欠账"时关闭。

```
turn/start
  claim next-step input + 一条 queued message
  assemble prompt sections + tool schemas
  -> agent/pre-step（waterfall：可 rewrite / reject）
      reject 或首个 enter 被改写为空 -> 无 step 关闭回合
      step/start
      agent/request -> prepareCall（取消则不提交任何东西）
      reconcile system/message
      append entered messages as user/message
      log request/header、request/context
      derive & freeze model history（从日志派生）
      stream the bound prepared call -> llm/stream -> agent/assistant-stream
      tool/call* -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result*
      step/end
      工具还欠请求，或 next-step input 到了 -> claim -> 下一个 step
  -> agent/turn-stopping（serial，停止回合）
turn/end
```

要点：
- `turn/*`、`step/*`、`system/message`、`user/message`、`assistant/message`、`assistant/attempt`、`tool/*` 是 **durable session 事件**；其余是三个域里的 live 扩展点。
- **重试不重跑装配、不重跑 `agent/pre-step`**（`architecture.md:110`）。
- 首个被 admit 的 step **先占系统头**，即使 prompt 为空（不发线消息）。

## 7. 会话日志：Model-visible ⟺ logged（最锋利的一条）

> **Model-visible means logged.** Every model request must be reconstructable from the log.

`deriveMessages()` 从 session log 投影出**模型历史**。每个 `assistant/message` **内嵌产生它的完整 compact 定时流**；`assistant/attempt` 保留 settled 的失败/重试/取消/流错误尝试，但**不进模型历史**。

推论：
- fork、resume、transcript、telemetry、持久化**全部从这些 durable settlement 派生**。
- 想在请求里加新东西 → **必须新增 session 事件**；改已有消息内容 → 注册**纯 message projection**（`subsystems/session.md`）。
- session 文件格式是**版本化 + 相邻迁移链**：`session.vN.jsonl[.zstd]`，提交过的代**永不重命名/替换/删除**；v0 用 `session.jsonl`。

> **对照 ai-coding**：我们的 `SessionData.messages` 是"状态"，dsh 把**日志当唯一真相源**。这是两套根本不同的心智模型，也是本系列最值得吃透的一条。

## 8. Capability seam（能力接缝）

一个**接缝** = 可替换能力的三个角色（`docs/glossary.md:9`）：

1. **Service Definition**——拥有 `ctx.<key>` 和词汇类型的 Cordis `Service`（抽象类或具体注册表，**不是** TS `interface`）
2. **Service Provider**——实现
3. **Consumer**——注入它，通常是面向模型的工具

典范是 `packages/shell`：`dsh-shell`（定义）/ `dsh-bash-local`、`dsh-bash-sandbox`（provider）/ `dsh-tool-bash`（consumer）。

> **接缝是完整能力，绝不是某一个角色。** 一个包可同时拥有多角色（当它们是一个关切时）。

威力（`architecture.md:134`）：**fs 与 subprocess provider 共享同一个执行世界**——把它们指向远端 sandbox，Bash、PTY、LSP **跟着一起搬**，无需 fork provider。

## 9. 术语表（精确用词，别混）

| 词 | 定义 | 出处 |
|---|---|---|
| **turn** | 一次 admitted input 的排空，在模型+工具停下或终止策略介入后结束 | glossary:37 |
| **step** | 一次模型请求 + 其响应触发的工具执行；turn 含 0..N 个 step | glossary:38 |
| **round** | 外层策略迭代，**含**一个 turn（如 goal round、Ralph attempt）；round 计数属于那个策略，**不数**会话里每个 turn | glossary:39 |
| **exchange** | 从"首个 step admit 人类输入"的 turn 起，到下一个此类 turn 的连续 turns；被 notice（subagent 结算、goal round、schedule）唤醒的 turn 留在前一个 exchange | glossary:40 |
| **scope** | 每-agent 注册单元：全局 或 scoped（恰好属于一个 scope key）；**两级、扁平，不下传给子 agent**；子树行为用 **lineage 数据**表达，绝不用 scope 结构 | glossary:11-21 |
| **goal** | 附在已有 session 上的 durable 完成目标，带 revisioned `active/paused/blocked/complete` 相位 + round 上限；**是状态，不是调度器**，session log 仍是其真相源 | glossary:25 |
| **human command** | `/` 前缀指令，由人类适配器经 `ctx.commands` 解释执行，**不成为模型消息** | glossary:31 |
| **Ralph loop** | 一个前台 fresh-agent 工作流，朝不可变目标跑；由 workflow + subagent 原语组成的**模型工具策略**，不是 goal/loop 模式/调度器 | glossary:44 |

> `scope` 的两级扁平 + "子树用 lineage 数据表达" 是一个反直觉但关键的设计——**避免作用域继承的复杂度**。
