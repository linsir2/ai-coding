## 算法 1：Cordis 五种派发

**问题**：一个事件要被 N 个 listener 消费，但"怎么消费"有五种不同语义（广播/并发/顺序/首个胜出/环绕拦截），不能混。

**实现**（`events.ts`，每种 ~5–10 行）：

```ts
isBailed(v) = v !== null && v !== false && v !== undefined   // "非空即胜出"

parallel(...args) { Promise.allSettled(dispatch('emit',args).map(cb=>cb(...args)))
                    → 有 rejected 则 AggregateError }        // 并发，等待全部
emit(...args)     { dispatch('emit',args).map(cb=>cb(...args)) } // 同步，丢弃返回值/promise
serial(...args)   { for (cb of dispatch('serial',args)) { r = await cb(...); if (isBailed(r)) return r } }
bail(...args)     { for (cb of dispatch('bail',args))   { r = cb(...);     if (isBailed(r)) return r } }
waterfall(...args){ cbs = dispatch('waterfall',args); inner = args.pop()
                    next = () => (cbs.shift() ?? inner)(...args)   // 环绕
                    args.push(next); return next() }
```

`dispatch()` 的过滤：
```ts
filter = thisArg?.[Context.filter]
hooks.filter(h => h.global || !filter || filter.call(thisArg, h.ctx))
     .map(h => h.callback.bind(thisArg))
```

**取舍**：
- **`serial`/`bail` 用 `isBailed`（非 null/false/undefined 即胜出）**，不用显式"stop"信号——**牺牲了表达力（不能返回 false 表示胜出），换来零 API 面**。
- **`parallel` 用 `allSettled` 而非 `all`**——**牺牲"首个错误立即抛"**，换来"所有 listener 都跑完再聚合错误"，因为清理类 listener 不该因兄弟失败被跳过。
- **`waterfall` 的 listener 顺序 = 注册顺序（可 `prepend`）**，且**每个 listener 拿到的是"下游的 next"**——这是 around-middleware，**veto 靠"不调 next"**。代价：**忘调 next 会静默短路下游**（AGENTS.md 专门立了纪律）。

## 算法 2：SurfaceManager —— 两阶段增量折叠

**问题**：surface 是"日志里产生消息的事件的有序视图"，会被 `replace` 改写。既要**每次 append 的 O(1)**，又要**替换的原子性**，还要**能校验候选而不污染已提交状态**。

**算法**（`surface.ts`）：

```
状态: nodes(Seq[]), replaceGeneration, contentGeneration, projectedMessages(Map)
      _lastProcessedSeq, _pendingPlan

两阶段：
  planSurfaceEvent(state, event) → SurfacePlan   ← 只校验，不改状态
  applySurfacePlan(state, plan)  → 提交，返回替换元数据

增量：_processDelta()
  for seq in (_lastProcessedSeq+1 .. tail):
    if _pendingPlan 匹配该 event → 复用它的 plan（避免重复校验）
    else applySurfaceEvent(...)
    _lastProcessedSeq = seq
```

**校验链**（一个 replace 要过四关）：
1. `replacementRange`：`indexOf(startSeq)`/`indexOf(endSeq)` 定位，`startIdx>endIdx` 拒绝。
2. `assertSourceEventReferences`：`sourceEventSeqs` 必须**稠密、无重复、全部早于当前 seq、且覆盖每个被遮蔽节点**。
3. `assertToolResultRewrite`：tool/result 替换**只能改 content**（其余字段 deep-equal）。
4. `assertSystemHeadRewrite`：**node 0 是 system/message 时，只有 system/message 覆盖恰好那一个节点才能替换**。

**取舍**：
- **`indexOf` 定位 = O(n)**。放弃"seq→index 映射表"（那会引入第二份表示，见 D6 决策），换来"一种表示 + 同样的渐进复杂度"。
- **两阶段（plan/apply）**：放弃"直接改再回滚"，换来"校验失败时状态零污染"——**同一模式在 token-meter 的 `_foldEvent` 重现**（"先跑所有可失败步骤再改状态"）。
- **`replaceGeneration` vs `contentGeneration` 两个计数器**：前者只数位置替换，后者数替换 + 消息投影。**分开是因为消费者需求不同**（纯 tail 增长 vs 内容重写）。
- **消息投影缓存不能比解释器活得久**（`_assertProjections`）：卸载一个用过的投影定义会**阻断缓存读取**——放弃"缓存可独立存活"，换来"不产生无法解释的缓存"。
- **`isDeepEqualJson` 手写**（替代 `node:util`）：放弃现成实现，换来**浏览器安全**（这个子路径被 web 客户端消费，`node:` import 会破坏 vite bundle）。

## 算法 3：`deriveMessages` —— 缓存 + 代数失效

**问题**：模型历史要从 surface 投影出来，但**每步都全量投影太贵**，且**改写的投影必须失效**。

**算法**：
```
每个 surface 节点只在**首次见到**时投影一次（缓存进 projectedMessages）
纯 tail 增长 → O(新增节点)
replace 或 消息投影（contentGeneration 变化）→ 重建
返回：每次新数组，但里面的 Message 是共享且 deep-frozen 的
```

**取舍**：
- **共享冻结消息 vs 每次 clone**：放弃"调用方可以改返回的消息"，换来"通过投影改日志历史**不可表示**"（改就抛）。**这是 D5"结构上不可能"的实例。**
- **`deriveEventMessage` 是公开的纯函数**：放弃"投影逻辑私有"，换来"外部重建器用**完全相同的规则**投影日志前缀，不可能与缓存不一致"。

## 算法 4：scope carrier 过滤 —— 祖先链上溯

**问题**：一个事件是"关于某个 agent 的活动"，但监听者可能注册在**它的祖先作用域**。事件要**向上流，不向下流**。

**算法**（`scope/index.ts`）：
```ts
scopeParents: WeakMap<ScopeKey, ScopeKey>   // 子 → 父

scopeTarget(base, key) 返回一个 carrier，其 filter：
  if baseFilter 不通过 → false
  tag = scopeOf(ctx)
  if tag === undefined → true                     // 无 tag 的 listener 全局接收
  for cursor = key; cursor; cursor = scopeParents.get(cursor):
    if cursor === tag → true                      // 沿 key 的祖先链上溯找 tag
  return false                                    // tag 在 dispatch key 之下 → 排除

bindScopeParent(key, parent): 若已有父则抛；linkScopeParent 做**环检测**（沿父链走，撞到自己就拒）
```

**取舍**：
- **祖先链每次 dispatch 上溯（O(depth)）**，而非维护"每个 listener 的可见集合"。放弃"O(1) 查找"，换来**关系只有一份**（一个 WeakMap 同时支撑"注册向下继承"和"事件向上准入"两个方向）。
- **绑定后不可重链**（除非持有原始 binding）：放弃"随意改祖先"，换来"链消费者可以放心走到根"。
- **WeakMap 而非强引用**：scope key 被回收则关系自动消失，**放弃显式清理**。

## 算法 5：工具调度 —— exclusive barrier + 有界滚动池

**问题**：一批工具调用要按 `executionMode` 混合串行/并行；并行的要限量；结果要**保持模型顺序**；abort/失败要**留下可重放的记录**。

**算法**（`tool-calls.ts`）：
```
主循环: 遍历 planned
  mode = executionMode(first)                     ← 每次分类前先 commit
  group = mode==='parallel' ? planned.slice(next) : [first]   ← 连续 parallel 段 / 单个 exclusive
  runGroup(group, mode)

runGroup:
  slots[], callSeqs[]            // 每个位置一个槽，保留 tool/call 的 seq 供结果引用
  fillPool:  while !aborted && nextToStart<len && inFlight<maxParallel:
               if nextToStart>0 && mode==='parallel' && 重分类后非 parallel → break（形成屏障）
               startCall(nextToStart); commitReady()
  commitReady: while committed<len && slots[committed] 就绪:
                 finalize/finish → appendToolResult（**按模型顺序**）→ 收 additionalContexts → committed++
```
- **abort**：停止补充，排空已启动，**为未启动调用 `appendSkippedToolCall`**（合成错误结果）。
- **调度失败**：排空已启动，reject；**拥有 step 的层记保守恢复结果**。

**取舍**：
- **"结果按模型顺序提交"**：放弃"谁先完成谁先落盘"，换来**重放确定性**（模型看到的 tool/result 顺序稳定）。
- **"分类前先 commit"**：每次启动前重读 `executionMode`，**使注册表变更能对未启动调用生效**（一个动态注册的工具可以中途变成屏障）。放弃"一次分类到底"。
- **abort 时给未启动调用合成结果**：放弃"只记录实际执行的"，换来**重放时 tool-call/result 配对不破**（否则历史里会有孤儿 call）。
- **分类是"一元"的**（Known Limitations）：安全性取决于比较兄弟的调用**必须 exclusive**——放弃并行度，换来正确性。

## 算法 6：compaction 范围选择 —— 尾部预算 + 配对平衡

**问题**：压缩要选一段"可以安全遮蔽"的历史：**保留最近的尾部**（上下文连续性），**不能拆散 tool-call/result 对**，**不能碰系统提示头**。

**算法**（`region.ts::selectCompactableRange`）：
```
firstIdx = systemHead(node0) ? 1 : 0            // node 0 是 system 则从 1 开始
// 从尾部向前累加 token，直到 >= retainTokens
accumulated=0; keepFromIdx=len
for index = len-1 down to 0:
    accumulated += pricedNodes[index].tokens
    keepFromIdx = index
    if accumulated >= retainTokens: break
if keepFromIdx <= firstIdx: return null          // 没有可压的

// 向前回退到 tool 配对平衡点
while keepFromIdx > firstIdx:
    if toolPairingBalancedBefore(surfaceNodes[keepFromIdx]): break
    keepFromIdx -= 1
if keepFromIdx <= firstIdx: return null

return { start: surfaceNodes[firstIdx], end: surfaceNodes[keepFromIdx-1] }
```

**取舍**：
- **"尾部向前累加直到预算"**：放弃"从头选固定条数"，换来**预算自适应**（大消息少留几条、小消息多留几条）。
- **"向前回退到配对平衡"**：放弃"任意切点"，换来**不产生孤儿 tool/result**（切点必须在 assistant tool-call 之前或其后 result 之后）。
- **node 0 保护**：放弃"压缩可以碰任何节点"，换来**系统提示永远在位**。
- **`systemHead` 只在 node 0 是 system/message 时保护**：后续 system 节点**可被压缩遮蔽**（它们是历史，不是当前提示）。

## 算法 7：token-meter —— 锚定测量（usage 基线 + 有符号启发式增量）

**问题**：要估算"当前请求的 token 压力"，但**纯启发式估算不准**（CJK/ASCII 混排），而**每次全量重算又贵**。

**算法**（`token-meter/index.ts::measure`）：
```
基线选择（按优先级）：
  1. 若有 anchor 且 header 匹配：
       - 若 anchor.usage 存在且 >= 该 anchor 的启发式价格 → baseline = {kind:'usage', tokens}
         （**provider 真值优先**，但它必须 >= 启发式价，保证有符号 delta 保守）
       - 否则 → baseline = {kind:'estimated', tokens: 启发式价}
       surfaceDeltaTokens = 当前 surface 价 - anchor surface 价      ← 有符号增量
  2. 无 header 且 surface=0 → baseline = {kind:'none', 0}
  3. 否则 → baseline = {kind:'estimated', 启发式价}
totalTokens = max(0, baseline.tokens + surfaceDeltaTokens)
```

估算本身（`estimate.ts`）：**固定密度 `CHARS_PER_TOKEN=4`**，每 block 加 `BLOCK_OVERHEAD=4`，每 message 加 `ROLE_OVERHEAD=4`。

**取舍**：
- **固定密度 4 chars/token**：放弃"精确 tokenizer"（要装依赖、要按 provider 分词），换来**零依赖、可预测**——注释明说"used only to drive compression thresholds, not exact"。**这正是 ai-coding `estimate_tokens` 的同款取舍**（但 dsh 用 provider usage 做锚点来纠偏）。
- **"锚点复用 + 有符号增量"**：放弃"每次全量重算"，换来 **O(surface) 而非 O(全部历史)**。前提是"header 不变 → 同一路由 → 可比较"。
- **"usage 必须 >= 启发式价才采用"**：放弃"无条件信 usage"，换来**有符号增量永远保守**（不会因基线偏低而算出负数）。
- **replay state 增量折叠**（`_sync` 只消费 `consumedEvents..session.seq`）：放弃"每次重读全日志"，换来增量。**同一"先校验后改状态"纪律**（`_foldEvent` 注释）。

## 算法 8：BlockAssembler —— 流折叠的"一个决定同时管内容和元数据"

**问题**：流式 chunk 要折叠成完整 block，但**截断（max-tokens）时丢弃 tool call 必须同时丢弃它的 replay 元数据**，否则"存储的元数据"与"存储的内容"不对齐。

**算法**：`BlockAssembler.push(chunk)` 累积；`blocks()` 组装；**max-tokens 丢弃所有 tool call**（截断的 call 不安全执行），**同一个丢弃决定同时剪掉 replay envelope 的 per-block 条目**（按位置）。`interruptedBlocks()` 只保留可安全定稿的前缀（有内容的 text/reasoning，不含 tool call）。

**取舍**：
- **"一个 keep/drop 决定覆盖内容和元数据"**：放弃"内容与元数据独立处理"，换来**`blocks()` 与 `replayState` 不可能不一致**——又一个"结构上不可能"。
- **对 delta-only 协议宽容**（无 block-start/end）：放弃"严格协议"，换来**兼容更多 provider**；但对**已关闭 index 的迟到 delta 忽略**（防坏适配器撑爆内存/损坏已完成 block）。
- **截断即丢 tool call**：放弃"保留部分 tool call"，换来"不执行不安全的半截调用"。

## 跨算法的共同模式（这才是精华）

| 模式 | 出现处 | 表述 |
|---|---|---|
| **两阶段：先校验后提交** | SurfaceManager `plan/apply`、token-meter `_foldEvent`、tool-calls `prepare/dispatch` | 可失败步骤全跑完再改状态 → 失败零污染 |
| **结构上不可能** | 冻结消息、`blocks()`≡`replayState`、`Message` 必带 id | 让不一致**不可表示**，而非检测 |
| **一份表示** | surface 用 seq 数组（不用映射表）、scope 用一个 WeakMap（两个方向） | 重复字节/复杂度换"一种可校验的表示" |
| **保守的有符号增量** | token-meter 锚点、tool-calls 合成结果 | 宁可高估/多记，不可低估/漏记 |
| **按模型顺序提交** | tool-calls `commitReady` | 重放确定性 > 完成顺序 |
| **零依赖启发式 + provider 真值纠偏** | token-meter estimate + usage 锚点 | 纯估算不准，但真值可锚定 |
| **校验链分层** | surface replace 四关、compaction 三关 | 每关只查一件事，失败即拒 |

## 对照 ai-coding

| 算法 | dsh | ai-coding | 可借鉴 |
|---|---|---|---|
| 派发 | 五种模式 | 仅 emit（`LoopObserver`） | **waterfall + serial** |
| surface 折叠 | 两阶段 + 增量 + 代数 | 无（直接改 messages） | **两阶段校验**思路 |
| token 估算 | 固定密度 + usage 锚点 | `estimate_tokens`（CJK 1/2，其他 1/4） | **usage 锚定纠偏** |
| 工具调度 | barrier + 有界池 + 模型序提交 | `dispatch_batch`（一票串行） | **模型序提交 + abort 合成结果** |
| 压缩范围 | 尾部预算 + 配对平衡 | 软水位 + 四层 | **配对平衡切点** |
| scope 过滤 | 祖先链上溯 | 无 | 单 agent 暂不需要 |
| 流折叠 | 一个决定管内容+元数据 | `ai/toolcalls.py` 合并增量 | **keep/drop 一致性** |
